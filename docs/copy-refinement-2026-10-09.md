## 유지한 표현

-   `숨은 추론`(IntentTrace)은 원본 README와 PRD의 표현이고, `데이터 형식 버전`(RELAY)은 이전 정리에서 `스키마`를 바꾼 표현이라 유지했다.
-   상세의 `적용 범위와 제약`은 2026-08-27에 `트레이드오프`를 바꾼 제목이라 되돌리지 않았다.
-   happyGallery 문제 16 한계의 `업무 책임`은 공개 요약 문서(`agent-feedback.md`)와 같은 표현이다.
-   `batonServicePresentation.js`의 `target`, `decision`, `result`는 어느 화면에서도 쓰지 않는 데이터라 문구 대상에서 뺐다. 지울지는 별도로 판단한다.

## 확인 필요

-   전자영장 연계 대상의 공식 명칭(`집행포털`, `전자영장 포털`, `포털`)은 2026-10-05부터 확인하지 못한 상태다. 경력 자료가 있어야 통일할 수 있다.
-   23번은 README의 `입력 크기 제한`만 근거로 썼다. 원본 실행 절차(`SKILL.md`)에 제한 이유가 따로 적혀 있으면 그 표현을 따른다.

승인하면 같은 의미가 노출되는 상세, 공유 이미지, 경로 메타, 검색 자료에 함께 반영한다.

## 반영 및 검증 결과

-   메인 문구 13곳(`projectSummaries.js` 12곳, `homeSkills.js` 1곳)을 바꾸고, 같은 문장이나 표현을 쓰는 `caseHighlights.js` 5곳(상세 소개 4곳, 확인한 범위 1곳)과 README BATON 항목을 함께 고쳤다. 테스트 기대값 1곳을 같은 의미의 새 문장으로 고쳤다. 이전 표현이 화면 문구에 남지 않은 것을 다시 검색했다.
-   새 글자는 글꼴 서브셋에 모두 있어 `font:check`가 통과했다.
-   `capture.mjs`로 메인, 전자영장, 군사법, BATON, Hope Commit, 청년정책메이트, 인쇄 화면을 1440·390px에서 검사해 14건 모두 통과했다. 메인 경력, 개인 프로젝트, 그 밖의 프로젝트, 학습과 기술 영역을 영역별로 캡처해 줄바꿈과 넘침을 직접 확인했다.
-   `og:generate`로 생성 기록을 갱신했다. 공유 이미지 문구 원본은 바꾸지 않았고, 바이트가 바뀐 PNG 6장은 글자 안티앨리어싱 차이다(이전 커밋에서도 같은 파일이 두 크기를 오갔다). `pdf:generate`는 4쪽으로 이전과 같고, 인쇄 화면 전체 캡처로 카드 배치를 확인했다(`pdftoppm`이 없어 PDF 직접 렌더링은 하지 못함).
-   `check:diff` 통과. `check:finish` 1회차에 검색 자료(BATON 개요 1건)가 다시 생성되어 diff를 검토한 뒤 2회차 통과(42개 파일 466건, 빌드).
