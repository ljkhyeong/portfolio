# 포트폴리오 문구 검토 — 2026-10-11

## 요청과 기준

사용자는 메인 제목 `외부 연동과 배치를 개발하는 Java 백엔드 개발자입니다.`가 심심하다고 했다. 해 온 개발에 맞춰 무엇을 말하려는지 한 번에 드러나는 문구로 바꾸고, 전체 문구를 포트폴리오의 취지에 맞게 고쳐 달라고 요청했다.

포트폴리오의 취지는 채용 담당자와 개발자가 첫 화면에서 **어떤 문제를 해결하는 개발자인지**와 그 근거를 읽게 하는 것이다. 그래서 기존 기준(실무 용어, 짧은 문장, 검증 수준 구분)에 더해, 노출 위치마다 이 메시지와 근거가 드러나는지를 확인했다. 범위는 `capture.mjs --all --expand --text`로 모은 전 화면 문구 1,945줄(메인, 상세 8개, BATON 서비스 6개, 문서 검색, 인쇄), 경로 메타, 공유 이미지 문구와 README다.

## 메인 제목

| 위치                                | 변경 전                                               | 변경 후                                                           |

| [메인 제목](src/data/homeHero.js:3) | 외부 연동과 배치를 개발하는 Java 백엔드 개발자입니다. | 외부 연동과 배치에서 중복과 누락을 막는 Java 백엔드 개발자입니다. |

이전 제목은 일하는 분야만 말하고, 그 분야에서 무엇을 해결하는지는 말하지 않았다. 프로젝트마다 반복해서 다룬 문제는 같은 요청이나 작업이 두 번 처리되는 **중복**과, 응답 유실이나 서버 중단으로 처리가 빠지는 **누락**이었다.

| 문제 | 근거(현재 포트폴리오)                                                                                                                                                            |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 중복 | 전자영장 이중화 서버의 `SKIP LOCKED` 작업 선점, BATON GO의 동시 요청 8건에 링크 1건, happyGallery 결제와 환불 재요청 방지, RELAY의 RabbitMQ 재전달 중복 처리 방지                |
| 누락 | 전자영장 중단 작업 재처리와 먼저 도착한 PDF 완료 응답 재조회(결과 누락 방지), 군사법 중단된 기관 배치 재실행, happyGallery 미전송 알림 Outbox 재처리, WATCH 미전송 이벤트 재처리 |

소개 문장(`멱등 처리, 동시성 제어, 중단된 작업의 재처리를 주로 구현해 왔습니다.`)은 제목의 방법에 해당하므로 그대로 두었다. 새 성과나 수치는 추가하지 않았다.

검토한 다른 후보와 고르지 않은 이유는 다음과 같다.

-   `데이터 중복과 누락을 막는 Java 백엔드 개발자입니다.` 짧지만 어떤 일에서 막는지가 빠진다.
-   `외부 연동과 배치를 중복도 누락도 없이 처리하는 …` 결과를 단정한다.
-   `기관 연계와 결제 연동에서 …` BATON의 이벤트 전달과 군사법 배치가 빠진다.
-   `… 데이터 정합성을 지키는 …` 실무 용어지만 구체적인 문제가 드러나지 않는다.

제목이 세 줄이 되어 `외부 연동과 배치에서 / 중복과 누락을 막는 / Java 백엔드 개발자입니다.`처럼 구절 사이에서만 줄을 바꾸게 했다([homeHero.js](src/data/homeHero.js:3)의 `headlinePhrases`, [HomeIntro.jsx](src/component/HomeIntro.jsx:26), [Home.css](src/css/Home.css:79)). 구절을 나누지 않았을 때는 1440px에서 `Java`가 둘째 줄 끝에 남고, 1200px에서 `누락을 / 막는`으로 끊겼다. 구절 하나가 화면보다 넓은 320px에서만 마지막 구절 안에서 줄을 바꾼다. PDF는 폭이 넓어 두 줄로 나온다.

## 유지한 표현

-   연표의 확인 결과(군사법 배치 재실행, 전자영장 성능, BATON 링크 1건, WebRTC 재생 지연)는 새 제목의 근거라 그대로 둔다. happyGallery의 k3s 자동 배포와 Hope Commit의 테스트 343개는 제목과 다른 내용이지만 확인한 결과라 유지했다.
-   경력과 개인 프로젝트 카드의 문제 해결 문장은 이미 중복(`SKIP LOCKED`, 멱등 키)과 누락(재처리, Outbox)을 구체적으로 쓴다.
-   상세 소개 첫 문장과 그 밖의 프로젝트 카드는 제품 설명이다. 바로 뒤에 맡은 일, 확인한 범위와 문제 칸이 있어 바꾸지 않았다.
-   `담당자 공백 및 업무 지연 등 5개 상태`의 `등`은 다섯 가지 중 둘만 적은 경우라 유지했다.
-   문서 검색 소개와 추천 질문은 이미 결제 중복 방지와 서버 중단 후 재처리를 다룬다.
