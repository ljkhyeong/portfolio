## 검증 범위 해석

-   운영 여부는 사용자가 확인한 `제공 결과`와 공개 보도로 판정했다. 이 저장소에서 운영 환경에 접속하거나 운영 지표를 확인하지 않았다.
-   운영 중 처리량, 장애 여부, 이중화 작업 선점의 운영 효과는 근거가 없어 쓰지 않았다. 100 RPS·300 TPS 결과는 계속 `성능 테스트 환경` 결과로 둔다.
-   개통일은 [warrantEvidence.js](src/data/warrantEvidence.js)의 `warrantOperation`에서 한 번만 정의하고 확인한 범위와 상세 메타에서 참조한다. README는 같은 문장을 직접 적었다.
-   공유 이미지 아래쪽의 `구현 내용과 테스트 결과`는 모든 프로젝트에 같은 안내라 유지했다.

포트폴리오의 테스트, 산출물 생성과 최종 빌드 결과는 `output/validation/last-run.md`에 기록한다.

## 담당 범위 정정(같은 날)

사용자가 담당 범위를 정정했다. 5개 기관이 함께 쓰는 전자영장 연계 서버는 사용자가 개발하지 않는다. 사용자는 해양경찰 형사사법정보시스템(KICS)에서 그 연계 서버와의 연계 기능과 배치를 개발한다.

| 위치                                                                 | 이전 표현                                                                     | 정정                                                                                  |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 메인 소개, README 소개                                               | 5개 기관이 실제 업무에 쓰는 전자영장 연계 서버를 개발합니다                   | 해양경찰 KICS에서 전자영장 연계 기능과 배치를 개발합니다                              |
| 경력 카드, 검색 요약, 상세 맡은 일, README 전자영장 항목             | KICS 요청을 통신사와 영장집행포털 형식으로 변환해 보내고 … 서버와 배치를 개발 | 해양경찰 KICS에서 5개 기관이 함께 쓰는 연계 서버와의 연계 기능과 배치                 |
| 상세 확인한 범위                                                     | 기관별 요청 변환 기능과 배치(Spring Batch)를 구현                             | 해양경찰 KICS의 연계 기능과 배치(Spring Batch)를 구현                                 |
| 기본 메타, `index.html`, 전자영장 메타                               | 5개 기관(이 쓰는) 전자영장 연계 서버                                          | 해양경찰 KICS의 전자영장 연계 기능                                                    |
| [도식](src/component/project/diagrams/WarrantIntegrationDiagram.jsx) | 강조 노드 `맡은 서버 / KICS 연계 서버 및 배치`                                | 강조 노드 `맡은 부분 / 해양경찰 KICS`, 별도 노드 `5개 기관 공용 / 전자영장 연계 서버` |
| 공유 이미지                                                          | 강조 단계 `기관별 규격 변환 / 연계 서버와 Spring Batch`                       | 강조 단계 `연계 기능과 배치 / 맡은 부분, Spring Batch`                                |

-   도식은 같은 960×560 좌표계에서 노드를 5개로 늘렸다. 연계 서버와 포털, 기관 사이의 흐름은 이전 도식과 같다. 연계 서버의 내부 기능은 확인하지 않았으므로 `요청 전달`, `자료 수신`만 적었다. 이전의 `기관별 형식 변환` 표기는 연계 서버의 기능인지 확인하지 못해 뺐다.
-   문제 해결 사례(이중화 서버의 작업 선점, OFFSET 조회 개선, 공통 처리와 기관별 처리 분리, PDF 완료 응답 재조회)와 성능 테스트 결과는 사용자가 이전에 제공한 담당 구현이므로 유지했다. 이 중 연계 서버 쪽 작업이 섞여 있으면 사용자 확인 후 고친다.
-   상세 테스트는 도식의 강조 노드가 해양경찰 KICS이고 연계 서버가 아닌지 확인한다.
