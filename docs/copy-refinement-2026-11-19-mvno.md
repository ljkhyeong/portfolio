# 별정통신사 문제 해결 후보 검토

사용자가 확인을 요청한 저장소의 소스 가이드, 결과 수집 역할 문서, 발송 및 재처리 코드와 관련 테스트를 대조했다. 내부 코드와 연계 규격은 공개하지 않고 설계 판단만 정리했다. 테스트 코드를 읽었으며 이번 검토에서 회사 시스템 테스트를 실행하지 않았다. 개발 완료, 통신사 테스트 중, 2026년 11월 27일 오픈 예정 상태는 사용자 제공 사실이다.

현재 화면은 유지하고 아래 내용을 추가 후보로 제안한다. 반영 위치는 `src/data/projects.js`의 전자영장 `problems`이며, `implementations`에는 기능 범위만 남긴다.

## 보조 후보

**일부 발송 실패에도 앞선 처리 결과 유지**: 여러 발송 단위 중 하나에서 오류가 나더라도 앞서 보낸 결과를 버리지 않도록 호출 예외를 실패 결과로 변환해 모읍니다. 발송 서비스 구현으로 확인했습니다. DB 저장까지 보장하거나 외부 발송을 롤백하는 구조는 아니므로, 별도 사례보다는 재처리 설명에 짧게 포함하는 편이 낫습니다.

## 편집 제안

-   1번과 2번을 우선 추가한다. 단순 파일/API 연계 설명보다 문제와 선택 이유가 분명하다.
-   3번은 동시성 판단을 더 보여줄 때 추가한다. 기존 이중화 배치 선점 사례와는 대상과 보장 범위가 다르다.
-   기존의 추상적인 ‘공통 처리와 기관별 변환 코드 분리’ 사례는 2번으로 대체할 수 있다. 사례 수를 무조건 늘리지 않는다.
-   결과 문구는 구현 또는 테스트 코드 확인 수준으로 쓴다. 운영 장애 감소율, 중복 발송 완전 차단, 파일과 DB의 원자적 처리 같은 미확인 성과는 쓰지 않는다.
