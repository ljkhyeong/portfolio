# F4·P4 개편 후 전체 검토 — 2026-10-06

메인 F4·상세 P4 개편(`docs/design-f4-2026-10-06.md`) 뒤 디자인 참고 표시를 지우면서 사이트 전체를 다시 검토했다. 문구와 노출 위치의 일관성, 코드와 접근성, 성능을 하위 에이전트 두 개가 읽기 전용으로 살폈고, 1440·390·320px 화면은 직접 확인했다. 새 성과나 수치는 더하지 않았다.

### 화면을 설명하던 문구와 장식

-   연표 아래 "막대 길이는 실제 기간입니다. 막대 옆 글은 …"를 지웠다. 좁은 화면과 인쇄본에서는 막대 옆이 아니어서 틀린 말이었다. 기간 범위만 남겼다.
-   연표 문구는 조건을 앞에 쓴다. 예: "성능 테스트 환경에서 100 RPS·300 TPS로 1시간 동안 모두 처리"
-   도식 머리의 영문 꼬리표(FLOWCHART / IDEMPOTENCY, SYSTEM ARCHITECTURE 등 13곳)를 지우고 제목과 설명 두 칸으로 바꿨다.
-   BATON 구성도 설명의 "서비스를 누르면 해당 상세로 이동합니다"를 각 서비스가 맡는 일로 바꿨다.
-   WebRTC 카드의 "처리 흐름 / 화면 캡처가 없는 교육 프로젝트"를 "맡은 부분 / 변환 서버와 재생 화면"으로 바꿨다.
-   BATON 서비스 상세의 "확인됨 / 미검증" 칸과 "검증 결과와 미검증 범위" 제목을 "확인한 것 / 아직 확인하지 않은 것", "확인한 범위"로 바꿨다. RELAY의 구현 문장은 확인한 것에서 구현 상태로 옮겼다.
-   상세 확인한 범위 상자에서 위 문장과 겹치던 보조 문장(청년정책메이트, IntentTrace, Hope Commit)을 지우고 개발 브랜치 구현만 남겼다.
-   화면에 보이는 가운뎃점 나열(카드 캡션, 서비스 링크 설명, 전자영장 처리 순서, 청년정책메이트 도식, README)을 풀어 썼다.
-   문서 검색 첫 화면 제목을 "프로젝트 문서 검색"으로 줄이고 원칙 목록을 문장으로 썼다.

### 접근성

-   메인 제목(h1)과 연표가 `header` 안에 있어 "본문으로 건너뛰기"가 건너뛰었다. 소개를 `HomeIntro.jsx`로 나눠 `main`의 첫 영역으로 옮겼다.
-   보이는 링크 글자가 접근 가능한 이름에 들어가게 맞췄다(학습 기록 보기, 연락처 GitHub, 상세 바로가기, 프로젝트 이동).
-   상세의 다른 문제 해결 색인은 h3 아래 항목이 다시 h3였다. h4로 바꾸고 항상 숨겨 두던 "상세 보기/접기" 글자를 지웠다.
-   휴대폰 메뉴는 가로 스크롤 영역이 초점 테두리를 잘라 냈다. 여백을 두고, 키보드로 이동하는 동안에는 오른쪽 흐림을 끈다(320px에서 확인).
-   학습 줄 막대 안에 이름을 쓰게 되면 흰 글자 대비가 2.9:1이라 본문 색을 쓰게 했다(지금은 막대 옆에 쓴다).

### 코드와 성능

-   연표 날짜 형식이 다르거나 끝이 시작보다 앞서면 바로 오류를 낸다. 이전에는 NaN으로 모든 막대가 조용히 깨졌다. `timeline.test.js`를 추가했다.
-   교육 과정 연표 이름을 `profile.js`(`timelineLabel`)로 옮겼다.
-   상세 첫 캡처의 `fetchpriority="high"`를 뺐다. 개편 뒤 1440×900에서 첫 캡처가 첫 화면 아래쪽(약 821px)에 걸리므로 제목 글꼴보다 앞설 이유가 없다. 넓은 화면 미리 받기는 유지했다.
-   검색 자료의 프로젝트 개요에 확인한 범위(`caseResults`)를 넣고 상태 이름을 화면과 같게(`status.label`) 했다.
-   쓰지 않는 데이터(`homeTypeLabel`, `homeProjectCategories`, `profile.role`·`site`·`education.type`), 맞는 요소가 없는 CSS(옛 연락처 링크, 쓰지 않는 연결선 색, 숨겨 두기만 하던 섹션 이동 이름표, 옛 헤더 인쇄 규칙)와 토큰 5개를 지웠다.
-   README의 옛 도면형 설명, 디자인 출처, 검증 단계 레일 설명과 `portfolio-project-refresh` 스킬의 `verificationRails.js` 안내를 현재 구조로 바꿨다.

## 의도된 동작이라 그대로 둔 것

-   확대 창은 화면 하나에서 열어도 그 프로젝트의 모든 화면을 순서대로 넘긴다. README와 테스트에 적힌 동작이다.
-   첫 화면 사진의 대체 텍스트 "임정규 프로필 사진"은 사진을 신원 정보로 쓰는 결정에 따라 남겼다.
-   상세 확인한 범위는 제목 대신 굵은 글자로 이름 붙인 영역이다. 화면 배치가 한 문장이기 때문이다.

## 제안 반영(같은 날 승인)

1. 메인 카드 화면: `npm run cover:variants`(`scripts/generate-cover-variants.mjs`)가 cwebp로 640·960px 사본을 만들고 카드에 `srcset`과 `sizes`를 단다. 청년정책메이트는 카드에 보이는 위쪽만 잘라 `homeImage`(780×488)로 둔다. 1440px·2배 화면에서 그 밖의 프로젝트 카드는 1440px 원본 대신 960px 사본(약 17KB)을 받는다. 사본 크기는 `scripts/cover-variants.test.mjs`가 WebP 머리글로 확인한다.
2. 연표 축 끝: 기준일 뒤 92일로 바꾸고 연도 눈금은 기준일이 든 해까지만 그린다. 지금(2026-10-05 기준) "지금"은 93.2%로 이전(93.5%)과 거의 같고, 1월에도 같은 자리에 머문다.
3. 공개 요약 문서: BATON 문서 6건의 가운뎃점 나열을 쉼표와 "와/과"로 풀고(`RPO·RTO`는 유지), `agent-feedback.md`를 합니다체로 맞췄다.
4. 대표 문서 수를 칸 대신 한 줄로 쓰고(상세와 BATON 서비스 공통), BATON 서비스 하단의 서비스 링크 반복을 지웠다(상단 서비스 전환 메뉴는 그대로).
5. 도식 노드의 영문 꼬리표를 짧은 한글로 바꿨다(INPUT → 입력, SOURCE / FOCAL → 미디어 서버, SUPERSEDED → 대체됨 등). 고유 이름(Spring API, Git, KICS)은 그대로 둔다. 내부 디자인 용어였던 FOCAL은 "핵심 처리", "맡은 배치"처럼 뜻으로 바꿨다. 공유 이미지의 BATON 서비스 흐름도에 남아 있던 파랑(`index.css` 기본 강조색)도 녹색으로 맞췄다.
6. Netlify 캐시: `/fonts/*`와 루트 `*.webp`에 `max-age=86400, stale-while-revalidate=604800`을 둔다. 파일 이름에 해시가 없으므로 오래 고정하지 않고, 하루 뒤부터는 이전 파일을 먼저 보여 주면서 새 파일을 확인한다.

## 확인하지 못한 것

-   실제 화면 낭독기에서 `summary` 안 제목(h4)을 읽는 방식, Safari·Firefox 화면, 느린 회선의 LCP는 확인하지 않았다.
-   기여 기록 히트맵의 휴대폰 첫 세 주에 달 이름이 없는 문제, 인쇄본에서 지연 로딩 이미지를 기다리는 시간은 그대로 두었다.
-   Netlify에 배포한 뒤 실제 응답 헤더는 확인하지 않았다(설정 문법은 Netlify 문서의 경로 규칙으로 확인).
