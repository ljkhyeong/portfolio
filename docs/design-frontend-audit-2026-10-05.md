# 디자인·프론트엔드 전면 점검 — 2026-10-05

## 판단

메인, 상세 8개, BATON 서비스 상세, 문서 검색과 404를 1440·1024·390px 전체 페이지로 캡처해 다시 봤다. 도면형 메인과 상세의 문제·구현·검증 구성은 읽기 목적에 맞아 전면 교체는 하지 않았다. 대신 같은 내용을 두세 번 보여 주는 부분을 지우고, 긴 목록을 접고, 테마에서 빠진 화면과 실제로 깨지는 규칙을 고쳤다. 코드 쪽은 사용하지 않는 CSS와 로딩 순서를 측정해 효과가 확인된 것만 적용했다.

## 사용하지 않는 CSS 정리

상세 화면의 `<main>`은 항상 `case-showcase`를 가지므로 `CaseShowcase.css`가 기본 규칙 대부분을 덮어쓴다. 덮여서 효과가 없던 규칙을 지웠다.

| 파일                      | 전(줄/바이트)  | 후(줄/바이트) |
| ------------------------- | -------------- | ------------- |
| `Project.css`             | 1,251 / 25,651 | 493 / 9,043   |
| `BatonService.css`        | 690 / 13,852   | 282 / 5,132   |
| `ScreenshotGallery.css`   | 496 / 10,531   | 290 / 5,705   |
| `CaseMetaSection.css`     | 134 / 2,939    | 82 / 1,462    |
| `ProjectEvidenceList.css` | 78 / 2,140     | 59 / 1,582    |

-   **검증:** 16개 경로 × 4개 폭(1440·1024·820·400) × CSS 로딩 순서 2가지(개발 서버, 운영 빌드 청크 순서)에서 기본·`details` 펼침·hover·focus·확대 창 상태의 모든 요소 위치·크기와 주요 계산값을 정리 전후로 비교했다. 의도한 수정 외에 위치·크기 차이는 없었다.
-   **함께 고친 결함:**
    -   860px 이하 BATON 상세에서 가로형 캡처가 3:4 세로 상자에 들어가 아래가 비었다. 갤러리 높이가 820px에서 1,674px → 1,190px, 400px에서 2,540px → 1,535px로 줄었다.
    -   청년정책메이트와 Hope Commit 갤러리의 첫 카드가 다른 카드보다 38px 길었다.
    -   `.case-meta*` 사본이 `Project.css`와 `CaseMetaSection.css`에 나뉘어, BATON 서비스 상세를 직접 열 때와 앱 안에서 이동할 때 여백이 달랐다. `CaseMetaSection.css` 한 곳으로 모았다.
    -   교육 상세의 상단 정보 여백이 CSS 로딩 순서에 따라 개발 서버 4px, 운영 28px로 달랐다. 28px로 고정했다.
-   **정리한 값:** `var(--x, #옛색)` 대체값 83개, 옛 어두운 테마 색(`#0d1117`, `#238636`, `.case-next`의 흰 글자), 항상 숨겨진 캡처 창틀 마크업과 스타일, 렌더링되지 않는 `.baton-service-index*`.

## 사이트 전용 글꼴 서브셋

사용자 승인을 받아 Pretendard 1.3.9 가변 글꼴 원본(`PretendardVariable.woff2`, 2,057,688바이트)과 fontTools 4.66.1·brotli 1.2.0을 내려받았다. 원본과 Python 도구는 임시 위치에만 두고 저장소에는 결과물만 넣었다.

-   **결과:** 사이트에 쓰는 673자(한글 포함, 주석 제외한 `src`·`index.html` 문구와 기본 ASCII)만 남긴 가변 글꼴 1개, 124,056바이트. 모든 굵기(45~930)와 `tnum` 같은 숫자 기능을 유지한다. 이전에는 메인에서 동적 서브셋 14개 366.5KB, 상세에서 17개 약 440KB를 받았다.
-   **로딩:** `index.html`에서 글꼴을 미리 받고 jsDelivr 스타일시트와 사전 연결을 지웠다. 문서 검색 화면은 공개 문서 원문을 보여 줘 서브셋에 없는 글자가 나올 수 있으므로 그 화면에서만 원본 동적 서브셋을 대체 글꼴로 불러온다.
-   **라이선스:** Pretendard는 OFL 1.1이며 "Pretendard"가 예약 글꼴 이름이다. 서브셋은 수정본이므로 글꼴 내부 이름과 CSS 글꼴 이름을 Portfolio Sans로 바꾸고, 저작권·상표·라이선스 이름 레코드는 원문을 유지했다. `public/fonts/LICENSE.txt`에 수정 내용과 라이선스 원문을 함께 둔다.
-   **누락 방지:** `npm run font:check`(빌드 전 검사)와 `scripts/font-subset.test.mjs`가 현재 화면 문구의 글자를 서브셋 기록과 비교한다. 새 글자가 생기면 실패하고 `npm run font:subset`으로 다시 만들라고 알린다.
-   **확인:** 메인 첫 화면 캡처는 이전 Pretendard와 글자 모양과 배치가 같고(힌팅 제거로 인한 미세한 안티앨리어싱 차이만 있음), 공유 이미지 15개와 PDF 10쪽에 빠진 글자가 없다. PDF는 1.30MB에서 1.21MB가 됐다.

## 2차 점검(푸시 후)

메인과 상세 8개, BATON 서비스 상세 6개를 1440·390px 전체 페이지로 다시 캡처하고, 전체 경로·두 폭에서 이름 없는 버튼·링크, 대체 텍스트 없는 이미지, 중복 ID, 제목 단계 건너뜀, 이름 없는 입력을 자동 점검했다(0건).

-   **모바일 갤러리:** 캡처를 화면 폭 그대로 한 장씩 쌓아 상세 길이의 큰 부분을 차지했다. 700px 이하에서는 옆으로 넘겨 보는 띠(다음 캡처가 14% 보이고 한 장씩 멈춤)로 바꿨다. 390px 전체 길이: 청년정책메이트 12,478 → 9,678px, BATON 12,169 → 10,932px, happyGallery 10,288 → 8,979px, ROUND 6,847 → 5,567px.
-   **넓게 두는 캡처 규칙:** 첫 캡처를 전체 폭으로 두는 규칙을 2열일 때(801px 이상)만 쓰고, 801~860px에서 청년정책메이트 첫 휴대폰 캡처까지 넓히던 규칙을 지웠다. 휴대폰 캡처 4장은 960px 이하에서 2열로 바꿔 캡션이 비좁지 않게 했다.
-   **서비스 갤러리 테두리:** 카드 테두리 안에 캡처 테두리가 겹치지 않게, 서비스 상세의 캡처에는 설명과의 구분선만 둔다.
-   **화면 검사 도구:** 요청이 시작되지 않은 지연 로딩 이미지는 `complete`가 참이라 전체 페이지 캡처에 빈 상자로 찍혔다(실제 화면은 정상). 캡처 전에 지연 로딩 이미지를 바로 불러오고 실제 크기가 생길 때까지 기다린다.
-   **배포 확인:** 푸시 후 배포된 메인은 글꼴 서브셋만 미리 받고, `/fonts/`는 하루 캐시로 제공되며, 상세 HTML에 화면 청크·첫 캡처 미리 불러오기가 들어 있다.

## 보류

-   **캡처 `srcset`:** 720w·1200w WebP를 두면 happyGallery 데스크톱 이미지가 약 265KB → 100KB가 된다. 저장소의 변환 도구가 Node 기반이 아니어서 생성 방식을 정한 뒤 진행한다.
-   **`projects.js` 분할:** 상세 청크의 89%가 8개 프로젝트 전체 데이터다. 프로젝트별 지연 로딩으로 상세마다 br 약 20~29KB를 줄일 수 있지만, 검색 자료 생성과 테스트가 같은 파일을 쓰므로 별도 작업으로 둔다.
