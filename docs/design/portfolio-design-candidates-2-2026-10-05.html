D. 도면

밝은 도면 바탕을 세로·가로 기준선으로 나누고, 첫 그림(Fig. 1)으로 BATON의 Core와 6개 서비스를 등각 선화로 그립니다. 이름과 한 줄 소개, 고정폭 메타 정보, 최근 1년 GitHub 기여 히트맵(실제 4,669회·145일)이 뒤를 잇고, 경력과 프로젝트는 도면 표처럼 줄로 정리합니다.

좋은 점

  • 개발자 포트폴리오에서 흔치 않은 질감이라 기억에 남음
  • 그림과 히트맵이 실제 구조·활동 기록이라 장식이 아님
  • 밝은 테마라 PDF와 디자인을 하나로 관리

아쉬운 점

  • 히트맵은 빌드 때 GitHub API로 받아야 함(토큰·실패 처리 필요)
  • 도면 질감이 과하면 본문이 가늘어 보일 수 있어 선 색 조절이 중요

영향 범위

  • 메인 전체와 공통 색 토큰, 상세 상단 배치
  • 기여 데이터 생성 스크립트 추가, OG·PDF 재생성

E. 스포트라이트 분할

왼쪽에 이름, 직무, 한 줄 소개, 메뉴와 연락처를 고정하고 오른쪽에서 소개, 경력, 프로젝트가 흐릅니다. 마우스를 따라 민트색 빛이 움직이고, 목록에 마우스를 올리면 그 항목만 밝아집니다. 지금의 어두운 녹색과 노란 아바타를 유지합니다.

좋은 점

  • 경력과 프로젝트를 날짜와 함께 위에서 아래로 바로 읽음
  • 움직임이 사용자 동작에만 반응해 읽기를 방해하지 않음
  • 지금 색과 아바타를 유지해 전환 비용이 중간 수준

아쉬운 점

  • 널리 따라 만든 배치라 원본과 비슷해 보일 수 있음
  • 모바일과 터치 기기에서는 빛과 강조 효과가 보이지 않음

영향 범위

  • 메인 레이아웃 재구성, 헤더를 왼쪽 고정 영역으로 이동
  • PDF는 기존 인쇄 배치를 따로 유지해야 함

F. 라이브 흐름

첫 화면 배경에서 요청이 실제로 흘러갑니다. 노란 중복 요청은 중복 확인에서 흡수되고, 정상 요청은 상태 저장에 기록을 남기며, 주황색 작업은 멈췄다가 재처리됩니다. 그 아래에서 대표 프로젝트를 실제 스크린샷과 함께 크게 보여 줍니다.

좋은 점

  • 첫인상이 가장 강하고, 움직임 자체가 전문 분야를 설명함
  • 스크린샷을 크게 보여 줘 구현한 화면이 바로 보임

아쉬운 점

  • 애니메이션 성능과 동작 줄이기 설정 대응이 필요함
  • 첫 화면이 길어 경력이 아래로 밀림
  • 계속 움직이는 배경은 오래 보면 산만할 수 있음

영향 범위

  • 메인 Hero 교체, 캔버스 컴포넌트 추가
  • 대표 프로젝트 배치 변경, OG·PDF 재생성
