-   글만 있는 대표 사례가 홀수일 때 마지막 사례 옆이 비는 배치(happyGallery 16, 전자영장 03, BATON 07): 한 줄을 다 차지하게 하면 다른 사례보다 중요해 보인다.

## 인쇄와 공유 이미지

-   카드를 flex로 바꾸면서 인쇄본에서도 소속 줄 아래 여백(2px)이 살아나 2쪽 경력 카드가 밀렸다. 인쇄 CSS에서 이 여백을 0으로 고정했다. PDF는 4쪽이고, PDFKit으로 그린 이전 PDF와 쪽마다 비교하면 글자 경계의 렌더링 차이(최대 384px, 밝기 차 10 이하)만 남는다.
-   홈 공유 이미지는 다시 생성해도 바이트가 같았다(지문 기록만 갱신).

## 2차 전수 검토 — 같은 날

### 방법

-   경로 17개와 404를 1440·1024·768·390·320px에서 캡처하고(85건), 접힌 내용을 모두 펼친 상태에서 페이지 전체 글자 대비를 검사했다. 실패는 0건이었다.
-   Playwright 측정 스크립트로 본문 선 어긋남, 격자 빈칸, 제목 마지막 줄의 한두 글자, 좁은 화면의 터치 영역, 제목 단계 건너뜀, 잘린 글자, 12px 미만 글자, 긴 줄(글자 크기의 48배 초과)을 찾았다. 덮여서 한 번도 적용되지 않는 CSS 선언은 요소마다 선언 값을 강제로 넣어 계산값을 비교해 찾았다(1440·390px).

### 확인하고 그대로 둔 것

-   BATON 서비스 `구현 상세`의 20px 들여쓰기: 펼침 표시 뒤 제목 글자에 맞춘 배치다.
-   좁은 화면의 작은 링크(소개와 연락처의 이메일·전화, 관련 링크, 검색 화면 아래 링크): 높이가 15~19px이지만 주변에 다른 누를 곳이 없어 WCAG 2.5.8의 간격 예외에 든다.
-   기여 히트맵의 달 이름(10px)과 연표 연도(11.5px): 축 이름표다.
-   덮여서 적용되지 않는 CSS 선언 78개: 대부분 상세 개편(P4) 때 `CaseShowcase.css`가 `Project.css`, `ProblemSolutionList.css`, 도식 기본값을 덮은 흔적이라 화면에는 영향이 없다. 지우려면 운영 빌드의 CSS 순서까지 비교해야 해서 이번 디자인 수정과 분리했다.
-   프로젝트 이동 메뉴와 이전·다음 링크의 분류(경력, 개인, 웹앱, 도구, 교육)가 메인의 묶음(경력, 개인 프로젝트, 그 밖의 프로젝트)과 다르다. 분류 이름은 문구 결정이라 바꾸지 않았다.
