# 도면형 다듬기 — 2026-10-05

## 판단

Claude Design 캔버스([포트폴리오 리디자인 시안](https://claude.ai/artifact/JAM4Pg2jeH5x9TaqHjcz2J), 비공개)에서 두 단계로 비교했다.

1. 새 방향 G(에디토리얼 이력서), H(벤토 대시보드), I(다크 엔지니어링 노트)를 실제 문구로 그렸다. 사용자와 함께 현재 도면형이 더 낫다고 판단했다. 세 시안은 다른 포트폴리오에도 쓸 수 있는 틀이었고, 현재 디자인의 Fig. 1(BATON 구성), 기여 기록과 검증 단계처럼 내용과 이어진 장치를 잃었다.
2. 현재 디자인을 유지하고 약한 곳만 고친 J·K·L을 현재 화면 캡처와 나란히 놓고 비교했다. 권장한 J와 K를 적용하고, 효과가 작은 L은 적용하지 않았다.

## 적용

| 시안                     | 약점                                                                                   | 변경                                                                                                                                                                                                                                                                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| J. 첫 화면에 확인한 결과 | 가장 강한 증거(전자영장 성능 테스트)가 경력 행 안의 작은 회색 글로 묻혀 있었다.        | 요청 처리 흐름 아래에 측정값 3개를 측정 조건, 출처 링크와 함께 둔다. 값 위에 도면의 치수선을 긋는다. 값은 `homeHero.js`의 `results`가 정의하고, 전자영장 수치는 `warrantPerformance`에서 읽는다.                                                                                                                                 |
| K. 홈에도 검증 단계 표시 | 홈의 "검증"은 회색 한 줄이고 상세의 검증 단계와 모양이 달라 같은 정보로 읽히지 않았다. | 경력의 전자영장 행과 BATON·happyGallery 카드에 상세와 같은 검증 단계를 둔다. `VerificationRail.jsx`에서 단계 목록을 `VerificationStages`로 분리해 두 화면이 같은 데이터(`verificationRails.js`)와 표시를 쓴다. 카드 안에서는 기준선 없이 칸으로 나눠 줄바꿈한다(`--compact`). 검증 단계가 없는 프로젝트만 확인 결과 문장을 쓴다. |

## 배치와 길이

-   1440px에서 경력 영역 시작이 760px에서 915px가 됐다. 첫 화면(1440×900)에는 경력 제목 대신 경력의 대표 결과를 포함한 측정값 띠가 들어온다. 띠 제목을 위 줄 대신 왼쪽 칸에 두어 처음 적용한 높이(984px)보다 줄였다.
-   900px 이하에서는 띠 제목을 위 줄로, 측정값을 한 열로 쌓는다. 700px 이하에서는 값 글자를 20px로 줄인다.
-   카드 안 검증 단계는 390px에서도 2×2로 놓인다(칸 최소 132px).

## 인쇄

검증 단계가 들어가 경력 행과 대표 프로젝트 카드가 길어지면서 PDF가 7쪽이 되고 1·2쪽 아래가 비었다. 다음과 같이 고쳐 6쪽을 유지한다.

-   경력 행과 대표 프로젝트 카드는 통째로 넘기지 않고, 문제·구현 목록, 검증 단계, 카드 소개와 상태 줄 단위로만 나눔을 막는다.
-   인쇄본의 경력 기간 칸을 150px로 줄이고 줄바꿈을 허용해 검증 단계 세 칸이 한 줄에 들어간다.
-   "프로젝트" 제목은 영역의 유일한 자식이라 제목 뒤 나눔 금지에서 빠지므로 따로 다음 내용과 붙인다.
-   측정값 띠는 A4 폭에서 제목 한 줄과 세 칸 한 줄로 둔다.

## 바로잡은 판단

비교 중 "제한된 범위에서 확인" 글자색이 대비 기준에 못 미친다고 적었으나, 글자는 이미 `#9a5c00`(약 5:1)이고 `#b06c00`은 기준이 3:1인 점 표시에만 쓴다. 바꾸지 않았다.

## 2차: 상세 하단과 모바일 첫 화면(M·N·O)

같은 캔버스의 "도면형 다듬기 2" 페이지에서 현재 화면 캡처와 나란히 비교했다. 권장한 N과 O를 적용하고, 효과가 작은 M(사용 기술 칩)은 적용하지 않았다.

| 시안                          | 약점                                                                                    | 변경                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N. 문서 수를 드러낸 대표 문서 | 문서 수(예: happyGallery ADR 49건, Idea 40건)가 접힌 "문서 분류와 작성 수" 안에 있었다. | 분류별 작성 수를 제목 아래 기준선 칸으로 펼치고, 문서는 유형 표시를 앞에 둔 한 행(제목·설명)으로 바꿨다. 프로젝트 상세와 BATON 서비스 상세가 공용 `DocumentList.jsx`를 쓴다. 표시하지 않게 된 분류별 설명 문장(`documentGroups[].summary`)은 데이터에서 지웠다. 수는 "40 / 1", "4개 서비스"처럼 단위가 섞여 있어 값 그대로 보여 준다. |
| O. 모바일 첫 화면 압축        | 700px 이하에서 설명을 숨긴 처리 흐름 2×2와 측정값 세 칸이 길게 쌓였다.                  | 처리 흐름을 화살표로 이은 한 줄로, 측정값을 치수선 없이 값·조건·출처 세 줄 행으로 줄였다.                                                                                                                                                                                                                                             |

-   390px 메인의 경력 영역 시작: 1,286px → 1,090px.
-   happyGallery 대표 문서 영역: 1440px 890px → 766px, 390px 1,369px → 1,246px(수 칸을 한 줄에 세 개).
-   서비스 상세의 문서 링크 이름도 프로젝트 상세와 같이 "… 대표 문서 새 창에서 보기"로 맞췄다.
-   인쇄본은 700px보다 넓게 그려 O의 영향이 없고 PDF는 6쪽을 유지한다.

## 3차: 검색, 문제 해결, 상세 상단, 그 밖의 프로젝트(P·Q·R·S)

같은 캔버스의 "도면형 다듬기 3" 페이지에서 비교했다. 권장한 Q와 S를 적용하고, P(검색 첫 화면에 검색 범위)와 R(상세 상단 표제란)은 적용하지 않았다.

| 시안                              | 약점                                                                                                                | 변경                                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Q. 접힌 문제 해결을 제목 목록으로 | 대표 사례 밖의 문제 해결(happyGallery 11건, BATON 10건)이 "추가 문제 해결 N건 보기" 안에 있어 제목도 보이지 않았다. | "다른 문제 해결" 제목 아래에 번호와 제목을 2열 색인으로 펼치고, 제목을 누르면 그 자리에서 문제 상황·적용한 방법·확인·제약을 펼친다(`ProblemSolutionList`의 `compact`).                     |
| S. 그 밖의 프로젝트에 검증 요약   | K 이후 BATON·happyGallery만 검증 범위가 보였다.                                                                     | 청년정책메이트, Hope Commit, IntentTrace, WebRTC/HLS 줄마다 검증 단계를 상태별로 묶은 한 줄(예: 확인됨 구현 · 자동화 테스트 · 공개 반영 / 미검증 외부 연동)을 둔다(`VerificationSummary`). |

-   문제 해결 영역 길이: happyGallery 1440px 1,443 → 1,778px, 390px 1,836 → 2,385px. 390px에서는 색인 글자와 간격을 줄여 처음 적용한 2,537px보다 줄였다.
-   그 밖의 프로젝트: 1440px은 링크 칸 높이 안에 들어가 588px 그대로, 390px은 918 → 1,107px.
-   함께 고친 결함: 문제 해결 제목과 대표 사례 제목이 사이트에서 불러오지 않는 `Pretendard Variable`로 지정돼 시스템 글꼴로 보였다. `var(--sans)`로 바꿨다.
-   인쇄: 검증 요약 줄로 7쪽이 되어 그 밖의 프로젝트의 링크를 가로로 놓고 간격을 줄여 6쪽을 유지했다.
