# RAG 검색 품질과 근거 확인 개선

2026-09-06, `9741d31` 이후 변경. 검색 API·문서 생성·검색 화면을 함께 개선했다.

## 변경

-   Elasticsearch 기본 분석기를 Nori로 변경했다. 임베딩 모델·차원·청크 설정과 함께 분석기도 호환성 검사에 포함한다. 기존 `v2` 자료를 삭제하지 않고 새 `v3` 인덱스를 사용한다.
-   happyGallery의 결제 confirm·알림 Outbox·스마트스토어 재고 ADR, 청년정책메이트의 자격 집계·마감 후보·AI 예약 복구 문서 6건을 본문으로 색인한다. 공개 허용 목록에서 선택했고, 공개 GitHub 원문을 커밋에 고정했다. 다른 외부 문서는 기존 설명만 유지한다.
-   본문이 같으면 문서 스냅샷의 이전 커밋을 유지한다. 관련 없는 저장소 커밋 때문에 문서 전체를 다시 임베딩하지 않도록 했다. 평소 빌드에서는 원문을 다시 내려받지 않는다.
-   API가 반환하는 발췌문을 화면에서 펼쳐 볼 수 있다. 본문 인용 번호를 누르면 해당 출처가 열리고 초점이 이동한다.
-   Caffeine으로 같은 질문의 임베딩만 2분·최대 256개 재사용한다. 자료 검색은 매번 실행하고, 실패한 임베딩은 캐시하지 않는다.
-   내부 상태 API와 `knowledge:sync` 명령으로 배포 자료 버전·문서 수·본문 해시의 일치를 확인한다. 버전이 다른 API는 수정하지 않고, 동기화 후 불일치도 실패로 처리한다.
-   CI에서 한국어 Elasticsearch 이미지와 검색 API 이미지를 만들고 실제 공개 자료로 동기화·검색 평가를 실행하도록 연결했다. 운영 서버의 배포 대상·비밀값은 설정하지 않았다.

## 검색 평가

대표 질문 20개와 근거 없는 질문 4개를 `scripts/knowledge-evaluation-cases.json`에 고정했다. 평가기는 검색 적중과 답변의 응답 계약을 구분하고, 답변 의미는 질문별 검토 기준을 남긴다.

| 자료·분석기        | 상위 5건 목표 문서 적중 | 1위 적중 | MRR@5 |
| ------------------ | ----------------------- | -------- | ----- |
| 기존 자료·standard | 20/20                   | 16/20    | 0.875 |
| 같은 자료·Nori     | 20/20                   | 18/20    | 0.950 |
| 본문 6건 보강·Nori | 20/20                   | 18/20    | 0.950 |

목표는 단순히 프로젝트가 맞는 문서가 아니라, 질문의 근거가 있는 지정 문서가 상위에 나오는지다. 문서 순위의 역수를 평균한 MRR@5는 1에 가까울수록 관련 문서가 위에 나온다는 뜻이다. 20개 질문에서의 결과이며 전체 질의나 실제 AI 답변의 정확도로 일반화하지 않는다.

같은 환경의 첫 실행 시간을 함께 저장했지만, 캐시 예열과 실행 순서의 영향이 있어 운영 지연 개선 수치로 사용하지 않는다. 질문 임베딩 재사용은 동일 질문에 대한 임베딩 호출이 한 번이고 문서 검색은 두 번 수행되는 테스트로 확인했다.

## 검증 범위와 남은 확인

-   실제 Elasticsearch에서 문서 색인·삭제, BM25·kNN, 조사 변형과 인덱스 호환성을 확인했다.
-   새 자료로 만든 실행 JAR에서 내부 동기화와 최종 해시 일치를 확인했다. API 버전 불일치·동기화 후 불일치·이미 최신인 경우는 별도 도구 테스트로 확인했다.
-   검색 화면에서 실제 로컬 검색 결과를 사용했다. AI 답변은 키가 없어 고정 응답으로 발췌문 펼치기·초점 이동을 확인했다.
-   실제 모델의 답변 정확도·근거 없는 질문 4개의 거절 품질·벡터 검색 품질은 미측정이다. `knowledge:evaluate -- --answers`를 AI가 설정된 평가 인스턴스에서 실행하고 결과의 `criteria`로 답변·원문을 검토해야 한다.
-   의미 검색 결과만 있을 때 AI를 호출하지 않는 기존 기준은 유지했다. 실제 모델의 품질 검증 없이 거절 기준을 완화하지 않았다.
-   원격 운영 배포와 운영 색인 변경은 실행하지 않았다. 배포 시 같은 자료로 API를 빌드하고 Nori가 설치된 새 인덱스로 전환한 뒤 `knowledge:sync`를 실행한다.

실행 명령과 설정은 [검색 API README](../knowledge-api/README.md), 로컬 측정 원본은 `output/validation/rag-*.json`에 있다. 검색 자료 버전은 최종 평가 보고서의 `verifiedSourceRevision`으로 확인한다.
