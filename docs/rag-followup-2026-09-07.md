# RAG 공개 원문과 검색 결과 및 운영 확인 보완

## 반영 내용

-   WATCH 이벤트 전달 ADR·공개 스테이징 검증 절차와 BRIEF 책임 분리 ADR·주간별 최신 보고서 조회 PRD의 원문 4건을 추가했다. 익명 GitHub 접근으로 공개 여부를 확인하고 원문 커밋에 고정했다. 기존 6건은 본문이 같아 기존 커밋을 유지했다.
-   공개 자료는 155건이며 외부 문서 본문은 10건이다. 비공개 Core·GO·RELAY 원문은 추가하지 않았다. 기존 공개용 설계 요약은 유지했다.
-   RRF로 결합한 순위에서 문서별 최상위 문단 하나를 선택한다. 긴 문서의 여러 문단이 결과를 중복 차지하던 문제를 줄였다. 후속 보완으로 답변에는 같은 문서의 추가 검색 문단도 전달한다. 문서당 최대 3개, 전체 본문 12,000자로 제한하고 실제 전달한 키워드 근거로 답변 가능 여부를 판단한다.
-   발췌문은 Elasticsearch의 일치 구간을 사용하고 CommonMark로 표시용 문법을 정리한다. 긴 발췌문은 문장·단어 경계에서 줄인다.
-   Spring 기본 HTTP 지표에 답변 상태와 검색 방식 횟수를 추가했다. Compose에서 관리 포트를 9091로 분리했고 호스트의 로컬 주소에만 연결한다.
-   이미 배포된 API를 대상으로 자료 버전 확인·동기화·검색 평가를 실행하는 수동 워크플로를 추가했다. 실제 AI 답변 평가는 명시적으로 선택할 때만 실행한다. 원격 서버 배포 자체는 포함하지 않는다.

## 검색 평가

기존 20개 질문에 WATCH·BRIEF 질문 4개를 추가했다. 근거 없는 질문 4개는 실제 AI 답변 평가용으로 유지했다. 아래 결과는 같은 공개 자료·Nori 분석기·AI 비활성 프로필에서 측정한 키워드 검색 결과다.

| 결과 선택 방식   | 상위 5건 목표 문서 적중 | MRR@5 | WATCH 재전달 검증 문서 순위 |
| ---------------- | ----------------------- | ----- | --------------------------- |
| 청크별 결과      | 23/24                   | 0.917 | 8위                         |
| 문서별 대표 문단 | 24/24                   | 0.925 | 5위                         |

문서가 검색 결과에 포함되는지 확인한 수치이며 AI 답변 정확도나 벡터 검색 품질을 뜻하지 않는다. 검색 자료 버전은 `sha256:0245a433eca3`이다.

## 확인한 범위

-   공개 문서 생성·동기화 기존 테스트, RRF 중복 문서 회귀 테스트, 검색·답변 서비스와 답변 상태 지표 테스트.
-   실제 Elasticsearch와 실행 JAR의 문서 155건·청크 220개 동기화 및 자료 버전 일치.
-   실제 API의 생성 불가·근거 부족 상태, 검색 방식 지표와 기본 HTTP 지표 조회. 업무 포트의 지표 주소는 404이고 별도 관리 포트에서 조회된다.
-   실제 검색 API를 연결한 데스크톱·모바일 검색 화면, 원문 링크와 BRIEF 상세의 새 문서 링크. AI 모델 응답은 이 화면 검증에 사용하지 않았다.
-   Compose·수동 검증 워크플로 구문과 포트폴리오 빌드. OG와 PDF는 생성 도구가 최신 상태로 판정했다.

## 답변 근거와 발췌문 후속 검증

-   단위 테스트 107건, Elasticsearch 통합 테스트 5건 통과. 대표 문단과 키워드 근거가 다른 경우, 추가 문단 인용, 선택 문서 범위와 입력 상한을 검증했다.
-   같은 공개 질문 24개에서 상위 5건 적중 24/24, MRR@5 0.925를 유지했다. 표 표시 추가 보완은 발췌문에만 영향을 주므로 검색 순위 평가는 반복하지 않았다.
-   BRIEF 실제 원문으로 제목·강조·링크·표 구분선 정리와 생략 표시를 확인했다. 1440×960·390×844 검색 화면에서 문서 링크 중복과 가로 넘침, 브라우저 오류가 없었다.
-   최종 포트폴리오 빌드와 산출물 검사 통과. 실행 기록과 화면은 `output/validation/rag-context/`에 보관했다.
-   실제 AI 모델의 답변 정확도는 측정하지 않았다. 테스트의 생성 응답은 문단 전달과 인용 연결을 확인하기 위한 대역이다.

## 응답 처리와 전체 인용 문단 보완

-   응답 본문을 읽는 도중·직후 취소된 요청이 빈 결과로 처리되지 않도록 수정했다. 잘못된 JSON을 받은 성공 응답은 읽기 오류로 안내하고, 429·503 등의 HTTP 오류 상태는 유지한다.
-   인용은 AI에 전달한 전체 근거를 반환한다. 검색용 280자 발췌문과 구분하며, 인용 번호를 누르면 전체 문단을 펼친다. Markdown 정리 로직과 기존 응답 필드를 재사용했다.
-   프런트엔드 17건과 Java 39건의 관련 회귀·HTTP 계약 테스트가 통과했다. 기존 검색 순위와 Elasticsearch 구현·설정은 바뀌지 않아 해당 검증은 반복하지 않았다.
-   Playwright에서 고정된 API 응답으로 416자 근거의 끝부분, 키보드 초점, 데스크톱·모바일 가로 넘침 없음과 잘못된 JSON 안내를 확인했다. 실제 AI 답변 정확도 평가가 아니다.
-   검증 로그는 `output/validation/rag-evidence/`, 화면은 `output/playwright/rag-evidence/`에 보관했다.

## 설정 확인 후 남은 작업

현재 작업 환경에는 OpenAI 키와 실행 중인 Ollama가 없고, 운영 API 주소도 설정돼 있지 않다. 실제 AI 모델 평가와 원격 검증은 실행하지 않았다.

-   평가 환경을 정한 뒤 `knowledge:evaluate -- --answers`를 실행하고 질문별 `criteria`와 인용 원문을 대조한다. 여러 문단을 종합한 답변의 의미와 출처 일치를 확인한다.
-   운영 서버가 준비되면 `knowledge-production` 환경에 API 주소와 동기화 키를 설정하고 배포 커밋을 선택해 수동 검증한다.
-   장기 지표 보관과 알림은 운영 모니터링 시스템에 연결할 때 구성한다.

실행 설정은 [검색 API README](../knowledge-api/README.md), 측정 원본과 화면은 `output/validation/rag-followup/`에 보관했다.
