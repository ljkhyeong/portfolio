# 메인 및 RAG 문서 검색 디자인 적용

2026년 9월 5일, 사용자가 승인한 메인 보완안을 적용하고 문서 검색의 디자인을 통일했다.

## 메인

- 픽셀 아바타 옆에 실명과 직무를 표시했다.
- 소개 다음에 회사, 재직 기간, 현재 및 이전 업무를 요약하고 경력 상세로 연결했다.
- 대표 프로젝트는 서비스 소개, 문제, 구현과 검증 범위 순서로 배치했다. 기존 프로젝트 데이터를 사용했다.
- 서비스 이미지는 작은 미리보기로 줄이고 모바일에서는 숨겼다. 제목과 상세 링크로 전체 내용을 확인할 수 있다.
- 그 밖의 프로젝트는 진행 상태, 짧은 소개와 상세 및 저장소 링크로 정리했다.
- 모바일의 요청 처리 흐름을 2 × 2로 배치했다.

390px 너비의 로컬 화면에서 소개 영역은 약 1,032px에서 588px로 줄었다. 경력 요약은 문서 상단 약 720px 지점에서 시작한다. 기기와 글꼴에 따라 달라지는 화면 측정값이다.

## 프로젝트 유형 및 컨소시엄 표시

메인 경력 요약과 전자영장 프로젝트에 `LG CNS 컨소시엄 참여`를 강조했다. 소속 회사인 BEINTECH도 함께 표시한다.

프로젝트 목록은 다음 네 구역으로 나눴다. 각 유형의 개수와 바로가기를 제공하며, 모든 프로젝트를 한 번씩 표시한다.

| 유형 | 프로젝트 |
| --- | --- |
| 경력 프로젝트 | 전송형 전자영장 시스템, 차세대 군사법 정보 시스템 |
| 웹앱 | BATON, happyGallery, 청년정책메이트, WebRTC/HLS 현장강의 보조 서비스 |
| 플러그인 | IntentTrace — IntelliJ 플러그인 및 MCP 연동 |
| AI 스킬 | Hope Commit — Codex 및 Claude Code 커밋 리뷰 스킬 |

Hope Commit의 원작 포크 출처와 WebRTC/HLS의 교육 프로젝트 표시는 유지했다. 상세 페이지에서 사용하는 기존 분류와 메인 화면의 유형은 별도 데이터로 관리한다.

유형 바로가기는 데스크톱에서 4열, 모바일에서 2열로 배치했다. 이동한 구역의 제목이 상단 메뉴에 가려지지 않도록 여백을 적용했다. PDF에는 유형별 제목과 프로젝트를 표시하고 바로가기는 제외했다.

## RAG 문서 검색

메인과 동일한 `PortfolioNavigation`과 `PortfolioTheme.css`를 사용한다. 별도 헤더를 제거하고 배경, 링크, 버튼, 입력창, 출처 및 오류 표시 색상을 맞췄다. 모바일 제목은 단어 단위로 줄바꿈한다.

검색 결과와 답변을 나눠 읽는 구성은 유지했다. 답변 영역에는 보조 배경을 적용해 검색 결과와 구분했다. API, 검색 필터, 사용자가 요청한 뒤 답변을 생성하는 동작과 출처 표시는 그대로 유지했다.

## 인쇄 및 공유 자료

PDF와 공유 이미지를 현재 소스 기준으로 다시 생성했다. 새 경력 요약과 프로젝트 검증 데이터도 생성물의 소스 변경 검사에 포함했다. 인쇄본은 밝은 배경을 유지하고 요청 처리 흐름을 세로로 배치한다.

## 검증

- `npm test`: 25개 파일, 테스트 164개 통과
- `npm run build`: 문서 검색용 자료 생성, 사이트맵, 공유 이미지, PDF와 경로별 메타데이터 검사 포함
- 브라우저: 320px, 390px, 768px, 1024px, 1440px에서 가로 넘침과 공통 색상 확인
- 검색 결과, 답변과 출처, 빈 결과, 서버 연결 오류 및 홈 이동 확인
- 다운로드 PDF 첫 페이지와 페이지별 텍스트 확인
- 유형별 2개, 4개, 1개, 1개 표시, 바로가기 이동, 전자영장 상세와 목록 복귀 확인

브라우저의 검색 상태 검증은 로컬 예시 API 응답으로 진행했다. 실제 검색 서버의 가용성이나 AI 답변 품질을 새로 평가한 작업은 아니다.

메인 및 RAG 디자인 캡처는 로컬 `output/playwright/design-implementation/`, 프로젝트 분류 보완 캡처는 `output/playwright/project-categories/`에 저장했다.
