# 포트폴리오 문구 검토 — 2026-10-17

## 요청과 범위

사용자가 포트폴리오 전체에서 너무 추상적이거나 이해하기 어려운 문구를 찾아 어떻게 바꾸면 좋을지 목록으로 달라고 요청했다. 기준은 실무 용어, 늘어지지 않는 문장, 간단하고 명확한 표현이며 메인 문구를 특히 간단하게 고치는 것이다. 이번에는 수정안만 정리했고 화면 문구는 바꾸지 않았다.

-   읽은 원문: `src/data/*.js`(메인, 상세, 대표 사례, BATON 서비스, 경로 메타, 공유 이미지, 검색 자료 생성 규칙), 고정 문구가 있는 컴포넌트(메인, 상세, BATON 서비스, 문서 검색, 인쇄, 404, 갤러리, 도식 5개), `index.html`, README.
-   개발 서버가 꺼져 있어 `capture.mjs` 수집 대신 원본 파일을 직접 읽었다. 어느 화면에 나오는지는 컴포넌트의 렌더링 경로로 확인했다. 화면에는 나오지 않고 검색 자료(`public/knowledge/portfolio.json`)에만 들어가는 필드(`summary`, `oneLine`, 서비스의 `detail`, `evidence`, `status`)는 `(검색 자료)`로 표시했다.
-   10월 5일부터 16일까지 승인한 문구, 메인 제목(2026-10-11 사용자 결정), 전자영장 담당 범위 표현(2026-10-11~12 사용자 정정)은 되돌리지 않았다. 새 성과나 수치는 더하지 않았고, 사실 확인이 필요한 항목은 `확인 필요`에 모았다.

## 결과 요약

-   메인은 10월 7일, 9일, 11일, 14일 검토를 거쳐 대부분 기준에 맞는다. 남은 것은 첫 화면에 설명 없이 먼저 나오는 약어(KICS)와 서비스 이름(BRIEF, CAL, ROUND), 한 문장에 두 가지를 쓴 카드 문장 두 곳이다. 5건.
-   상세와 BATON 서비스 화면에는 영어 그대로 쓴 말(standalone, hover), 무엇과 비교하는지 빠진 말(출생일 기준 차이, 3단계 결과, 접수 및 최종 결과 분리), 확인 칸에 쓴 구현 내용, 같은 환경을 네 가지로 부르는 이름(배포, 공개, 원격, 공개 배포)이 남아 있다. 29건.
-   추천 질문, 문서 검색 안내와 오류 메시지, 도식 노드, 대체 텍스트는 10월 14일과 16일에 정리한 상태가 유지돼 고칠 곳을 찾지 못했다.
