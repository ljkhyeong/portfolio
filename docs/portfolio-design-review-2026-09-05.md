# 포트폴리오 디자인 비교 및 보완 제안

검토일: 2026년 9월 5일

적용 상태: 사용자의 보완안 승인에 따라 메인과 RAG 문서 검색 디자인을 적용했다. 아래는 적용 전 비교 기록이며, 실제 변경과 검증 결과는 [적용 결과](portfolio-design-implementation.md)에 정리했다.

## 결론

전면 교체보다 **현재 디자인을 유지하고 메인의 정보 배치를 보완하는 방향**을 추천한다. 어두운 녹색, 노란색 픽셀 아바타와 요청 처리 도식은 중복 실행 방지와 중단 작업 재처리를 설명하는 현재 포트폴리오에 잘 맞는다. 프로젝트 상세에 담당 범위, 문제, 구현과 검증 근거가 이미 있어 이를 유지할 가치가 있다.

보완할 부분은 이름과 경력을 찾는 순서, 대표 프로젝트의 높이, 모바일 첫 화면의 길이다. 채용 담당자와 기술 면접관이 백엔드 경력과 구현 사례를 확인하는 상황을 기준으로 판단했다. 실제 방문자 행동이나 채용 성과를 측정한 결과는 아니다.

[현재 화면과 보완안 비교 시안](design/portfolio-design-review-2026-09-05.html)

## 검토한 범위

- 현재 메인: 소개, 대표 프로젝트 3개, 추가 프로젝트 5개, 경력 및 학습, 기술, 연락처
- 데스크톱 1440 × 1000과 모바일 390 × 1000의 화면
- BATON 상세와 문서 검색 화면의 구성 및 메인과의 연결
- 아래 GitHub 저장소와 연결된 사이트. Simplefolio와 developerFolio는 저장소 설명을 중심으로 비교했다.
- 기존에 참고한 Hamish Williams와 CraftzDog의 현재 사이트

이번 검토에서 프로젝트 상세 전체를 새로 전수 점검한 것은 아니다. 전면 개편 여부를 판단하기 위해 메인과 대표 상세의 디자인을 비교했다.

## 현재 화면에서 확인한 점

| 항목 | 관찰 | 보완 방향 |
| --- | --- | --- |
| 첫 화면의 이름 | 상단에 GitHub 계정명이 있고 실명은 하단 연락처에 있다. | 상단에 `임정규 / 백엔드 개발자`를 표시한다. |
| 경력 위치 | 회사와 재직 기간은 소개에 있지만 경력 상세는 프로젝트 8개 뒤에 있다. | 소개 다음에 회사, 현재 업무, 이전 업무를 간단히 보여준다. 자세한 경력은 기존 섹션으로 연결한다. |
| 대표 프로젝트 | 도식 또는 큰 서비스 화면과 설명을 나란히 배치한 세로 목록이다. | 이미지 크기를 줄이고 담당 문제와 구현 내용을 먼저 읽게 한다. |
| 첫 소개의 높이 | 390px 너비에서 소개 영역이 약 1,032px다. 프로젝트 섹션은 문서 상단 약 1,164px에서 시작한다. | 모바일 처리 흐름을 2 × 2로 압축하고 여백을 줄인다. |
| 경력까지의 거리 | 경력 섹션은 데스크톱 약 4,428px, 모바일 약 7,593px 지점에서 시작한다. | 경력 요약을 앞으로 옮겨 실무 경험을 먼저 확인하게 한다. |
| 상세 페이지 | 문제와 구현, 도식, 검증 자료를 깊게 읽을 수 있다. | 유지한다. 메인은 사례 선택에 집중한다. |
| 문서 검색 | 메인 및 상세와 달리 밝은 바탕이 사용된다. | 공통 색상과 제목, 입력창 스타일을 맞추는 작업을 후순위로 진행한다. |

위 높이는 당시 로컬 프로덕션 미리보기에서 측정한 CSS 픽셀이다. 기기, 글꼴과 화면 너비에 따라 달라진다. 화면 캡처의 지연 로딩 이미지도 별도로 확인했다.

기존 참고 사이트도 다시 확인했다. [Hamish Williams](https://hamishw.com/)는 제품 화면과 디자인 작업을 크게 보여준다. 현재 포트폴리오에서는 그 표현을 유지하되 서비스 화면의 비중을 줄이는 편이 적합하다. [CraftzDog](https://www.craftz.dog/)는 개인 소개와 제품 활동을 짧게 연결한다. 간결한 프로필은 참고하되, 제품 홍보보다 경력과 문제 해결 사례를 앞에 둔다.

## 적용할 보완안

1. **이름과 현재 업무를 첫 화면에 표시한다.** 계정명보다 실명과 직무를 먼저 보여주고, 회사 및 재직 기간을 함께 둔다.
2. **경력 요약을 대표 프로젝트 앞에 둔다.** 전자영장 연계 서버 및 Spring Batch 개발, 이전 군사법 자료 검증 배치를 짧게 연결한다. 경력 본문을 전부 복제하지 않는다.
3. **대표 프로젝트에서 문제와 구현 내용을 먼저 보여준다.** 서비스 설명은 한 문장으로 두고, 기존 `homeFacts`와 검증 범위를 활용한다. 수치나 구현 상태를 새로 만들지 않는다.
4. **이미지와 처리 흐름의 높이를 줄인다.** 데스크톱에서는 작은 보조 이미지, 모바일에서는 간단한 처리 흐름을 사용한다. 전체 화면과 아키텍처는 상세에서 읽는다.
5. **나머지 프로젝트를 짧은 목록으로 정리한다.** 각 프로젝트의 제목, 핵심 경험과 상세 링크를 남긴다. 경력, 기술, 연락처까지 이어지는 길이를 줄인다.
6. **문서 검색의 시각적 일관성을 맞춘다.** 메인과 상세에서 쓰는 색상, 글자 크기와 입력창 규칙을 적용한다.

우선 적용 범위는 1~5번이다. 6번은 메인 보완 후 별도 변경으로 나누는 편이 확인하기 쉽다.

## 시안의 디자인 기준

- 색상: 현재 배경 `#171a19`, 보조 배경 `#222925`, 본문 `#f4f6f4`, 보조 글자 `#b2beb6`, 녹색 `#a6d9bd`, 노란색 `#f4d35e`를 유지한다.
- 글꼴: 현재 Pretendard 계열을 유지한다. 첫 제목은 데스크톱 46px, 모바일 32px, 일반 본문은 17px를 기준으로 시안을 만들었다.
- 배치: 왼쪽 정렬을 유지하고 소개, 경력 요약, 대표 사례, 추가 프로젝트 순서로 읽게 한다. 세로 목록마다 큰 이미지를 반복하지 않는다.
- 특징: 현재 픽셀 아바타와 실제 요청 처리 순서가 기억에 남는 요소다. 새 장식, 배경 효과나 애니메이션을 추가하지 않는다.

```text
이름 및 메뉴
소개 문구                     요청 처리 흐름
회사 및 재직 기간              현재 업무 / 이전 업무
대표 프로젝트                 문제 / 구현 / 검증 범위
추가 프로젝트 짧은 목록
기존 경력 상세 / 기술 / 연락처
```

초안에서 고려한 고정 프로필 사이드바는 제외했다. 현재 메인의 넓은 도식과 한글 설명을 살리고, 모바일에서도 같은 읽는 순서를 유지하기 위해서다. 시안은 이 배치의 타당성을 확인하는 용도이며, 프로덕션 화면에는 아직 적용하지 않았다.

## 구현 시 참고

- `src/data/homeHero.js`, `profile.js`, `projectSummaries.js`의 사실관계를 유지한다.
- 메인 제목의 줄바꿈, 요청 처리 도식, 경력 요약과 대표 프로젝트 목록부터 조정한다.
- 기존 React와 CSS로 구현할 수 있다. 참고 저장소의 프레임워크로 교체할 이유는 없다.
- 문구, 라우트, PDF 링크를 유지하고 데스크톱 및 모바일의 줄바꿈과 넘침을 확인한다.
- 이 문서와 HTML은 검토 결과 및 시안이다. 실제 사이트, PDF와 프로젝트 데이터는 변경하지 않았다.
