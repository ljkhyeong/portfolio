## 우선 수정할 불일치

1. `src/data/projects.js:441`의 BRIEF 설명은 “Core 화면에는 아직 연결하지 않았습니다”라고 한다. 현재 Core의 `frontend/src/features/brief/BriefEditionSection.tsx:118`에 “지난주와 바로 비교” 버튼이 있고 `frontend/tests/e2e/brief-navigation.spec.ts:243`에 대응 시나리오가 있다. Core README는 저장 이후 변경 확인도 설명한다. 화면 연결은 구현됨으로 고치되, 공개 HTTPS 운영 검증은 별도로 남겨야 한다.
2. 청년정책메이트 문서 수는 `src/data/projects.js`에서 설계 11·구현 기록 73으로 표시한다. 같은 공개 main의 `git ls-tree` 기준 `docs/design`은 10개, `docs/development`는 67개다. 수치를 갱신하거나 문서 개수 대신 대표 설계 근거를 보여 주는 편이 유지하기 쉽다.
3. 청년정책메이트 캡처는 `2065081` 기준이다. 10월 30일 근거 문서에도 홈 캡처에 정책 40건이 남아 있다고 명시돼 있다. 현재 설명의 로컬 수집 90건·검토 정책 15건과 촬영 시점이 다르므로 홈과 상세 캡처를 함께 교체할 필요가 있다. 이번에는 이미지를 새로 촬영하거나 시각 검사하지 않았다.

## 프로젝트별 반영 후보

-   **BATON Core·BRIEF:** 요약 버전 비교, 지난주 비교, 저장 이후 변경 확인과 미해결 기간 표시. Core README·HANDOFF와 BRIEF 후속 변경 `1a7269a`, `9bedde0`, `6d30c42`가 근거다. 계정 권한 팀과 초대·권한 회수, 실패 이벤트의 지수 백오프도 현재 대표 사례보다 발전한 부분이다. 단순 서비스 분리 소개에서 실제 연동 과정의 권한·재시도 문제 해결까지 드러내면 좋다.
-   **WATCH:** README는 서로 다른 호스트의 무응답을 구분해 다섯 번째 호스트부터 내부 실패로 처리하고 `BROKEN` 전파를 억제한다고 명시한다. 이전 토큰 하나를 함께 허용하는 API 토큰 교체도 구현돼 있다. 대상 장애와 점검 서버 측 연결 장애를 구분한 사례가 기존 SSRF 차단 설명을 보완한다. 네 곳 이하 실패는 대상 실패로 판단한다는 한계도 유지한다.
-   **CAL:** README의 전체 시즌 투영 재생성과 구독별 최근 조회일 기록을 반영할 수 있다. 최근 조회일은 UTC 날짜만 남기고 IP·경로·클라이언트 정보를 기록하지 않는 범위를 함께 적는다. 실제 캘린더 앱 구독 검증 완료로 확대하지 않는다.

-   화면·PDF·OG·검색 결과의 실제 렌더링은 검사하지 않았다. 제품 코드 변경이 없어 관련 테스트·빌드는 실행하지 않는다.
