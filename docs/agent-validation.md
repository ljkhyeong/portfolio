# 에이전트 검증 절차

## 기존 세션에서 확인한 반복 작업

2026-09-05에 `포트폴리오 문구 명확성 점검`과 `메인 소개 문구 명확화`의 최근 완료 작업을 검토했다.

| 확인한 사례 | 개선 |
| --- | --- |
| 공통 기술 링크 7개를 제거한 작업에서 상세 이미지를 포함한 OG 전체 생성에 약 35초가 걸렸다. | 홈과 상세 이미지의 입력 파일을 분리하고 최신 파일은 생략한다. |
| 분류 변경 작업에서 빌드 후 PDF 페이지 배치를 고쳐 PDF 생성과 빌드를 다시 실행했다. | 화면과 인쇄 배치 수정 후 산출물을 만들고 최종 빌드를 실행한다. |
| 빌드 전후에 같은 배포 원본 PDF를 두 번 검사했다. | 빌드 전 검사를 유지하고 메타데이터 생성기의 중복 검사를 제거했다. |
| 작은 문구 변경에도 전체 테스트를 실행했다. | 관련 테스트를 먼저 선택한다. 공통 동작이나 의존성 변경, CI에서는 전체 테스트를 실행한다. |
| 메인과 상세 디자인을 전체 확인한 뒤에도 다음 검토에서 도식의 글자 대비 문제를 발견했다. | 방문한 페이지 수보다 변경된 요소의 대비, 줄바꿈과 실제 동작을 확인한다. |

수정이나 실패 뒤의 재실행은 필요한 검증이다. 같은 입력으로 통과한 검사를 근거 없이 반복하는 일을 줄인다.

## 검증 순서

1. `git status --short`와 diff로 이번 변경을 확인한다. 이전 기록이 있으면 입력 파일, 의존성, 실행 환경이 그대로인 성공 결과만 재사용한다. 커밋 ID만 같다는 이유로 미커밋 변경을 무시하지 않는다.
2. 아래 표에서 필요한 검증을 고른다. 실패하면 해당 원인을 수정하고 영향받은 검사부터 다시 실행한다.
3. 화면과 인쇄 배치 수정을 마친 뒤 필요한 PDF와 OG를 생성한다. 생성 명령은 최신 파일을 생략한다. 렌더링 코드를 바꾸면 `scripts/artifact-inputs.mjs`의 입력 목록도 확인한다.
4. 배포에 영향을 주는 변경은 마지막에 `npm run build`를 실행한다. 검색 자료 생성과 sitemap, OG, PDF 검사는 이 명령에 포함된다.
5. 선택한 검사와 필요한 화면 확인이 끝나면 커밋한다. 새로운 변경, 실패나 미확인 위험이 없으면 검증 범위를 더 넓히지 않는다.

## 변경별 확인 범위

| 변경 | 확인 |
| --- | --- |
| 지시 및 개발 문서 | 참조 경로, 명령, `git diff --check`. UI 테스트나 이미지 생성은 필요하지 않다. |
| 화면 문구 및 프로젝트 데이터 | 관련 화면과 링크, 영향받은 기존 테스트. PDF와 OG는 생성 입력이 바뀐 경우 갱신한다. |
| 컴포넌트 동작 | `npm test -- <관련 테스트 파일>`, 변경한 동작과 오류 상태. |
| 스타일 | 변경한 화면의 데스크톱과 좁은 모바일, 글자 대비, 줄바꿈과 가로 넘침. 공통 스타일이면 메인과 대표 상세, 영향을 받는 도식도 확인한다. |
| 라우팅, 공통 상태, 의존성 | `npm test`, 영향받은 경로 이동과 최종 빌드. |
| 산출물 생성 스크립트 | 관련 `scripts/*.test.mjs`, 실제 생성, 무변경 재실행에서 파일 유지 여부와 최종 빌드. |
| 검색 API | `knowledge-api/README.md`의 관련 검증. 프런트엔드 문구 수정만으로 서버 테스트를 실행하지 않는다. |

전수 검토 요청에서는 메인, 상세, 검색, 인쇄 등 확인 범위를 기록한다. 다음 검토는 기록의 누락과 새 변경부터 확인하되, 새 전수 검토 요청은 그 범위에 맞게 수행한다.
외부 폰트나 브라우저 변경은 파일 해시로 감지할 수 없으므로 필요한 생성 명령에 `--force`를 붙인다.
Netlify의 전체 테스트와 빌드, 검색 API CI의 검증은 유지한다.

## 다음 세션에 남길 기록

`output/validation/last-run.md` 한 파일을 갱신한다. 커밋에 포함하지 않는다.

- 검증한 커밋과 변경 파일. 미커밋 상태라면 그 사실도 적는다.
- 실행한 명령, 결과와 확인한 화면 범위.
- 실패 원인, 미확인 항목과 다음에 필요한 검사.

이전 세션은 먼저 요청, 최종 결과와 검증 명령만 확인한다. 전체 도구 출력과 diff는 실패 원인을 확인할 때 필요한 부분만 읽는다.
긴 로그는 파일로 남기고 종료 코드와 실패 부분을 확인한다. 같은 문서나 로그를 반복해서 전체 출력하지 않는다.
