# 포트폴리오 문구 검토 — 2026-10-17 성과로 약하게 읽히는 문구

## 요청과 범위

사용자가 메인의 `중단된 기관 배치만 찾아 재실행`, 전자영장 성능 테스트(100 RPS·300 TPS, 1시간), Hope Commit의 `GitHub Actions에서 자동화 테스트 343개 통과`가 별것 안 한 것처럼 읽힌다고 지적했다. 같은 유형을 전수 검토해 뺄 것은 빼고 고칠 것은 고쳐 달라고 해서 검토와 반영을 함께 했다.

-   대상: 메인의 성과 문장 전체(연표 6개, 경력 카드 2개, 개인 프로젝트 카드 2개, 그 밖의 프로젝트 카드 4개, 소개, 학습과 기술)와 같은 뜻이 나오는 상세의 확인한 범위, 맡은 일, 경로 메타, README, 검색 자료.
-   새 성과나 수치는 더하지 않았다. 바꾼 문장은 데이터에 이미 있던 사실(개통일과 운영 여부, 상세 문제의 제약과 확인 문장, 공개 저장소의 CI 작업 이름)로 썼다.
-   메인 제목(2026-10-11 사용자 결정), 메인 소개(오늘 오전 승인), 전자영장 담당 범위 표현(2026-10-11~12 사용자 정정)은 바꾸지 않았다.

## 판단 기준

약하게 읽히는 문구는 세 유형이었다.

1. **절차를 성과로 쓴 문장.** `중단된 기관 배치만 찾아 재실행`은 누구나 하는 조작으로 읽히고, 실제로 한 일(통합 모니터링 없는 폐쇄망에서 원인 단계 추적, 자료 반영까지 복구)이 가려진다.
2. **개수를 성과로 쓴 문장.** `자동화 테스트 343개 통과`, `서버 테스트 264개`는 무엇을 확인했는지 말하지 않는다.
3. **비교 기준 없는 수치.** `100 RPS·300 TPS로 1시간 동안 모두 처리`, `동시 요청 8건`은 목표치나 전후 비교가 없어 숫자만 작게 보인다. 이런 수치는 상세에서 해당 설계의 검증 근거로 둘 때 뜻이 생긴다.

그래서 연표의 막대 옆 글 기준을 `확인한 결과와 조건`에서 `프로젝트마다 가장 강한 사실 하나`로 바꿨다. 실제 운영과 전후 비교 측정값을 먼저 쓰고, 없으면 맡은 범위나 해결한 문제를 쓴다. 쓸 만한 사실이 없으면 글을 두지 않는다.

## 3. 검토했지만 유지한 표현

-   전자영장 성능 테스트의 수치와 조건(100 RPS·300 TPS, 1시간). 메인과 README에서는 뺐지만 상세 문제 04의 확인과 확인한 범위에는 그대로 둔다. 작업 선점과 트랜잭션 분리 뒤 커넥션 풀 고갈, 오류, DB 잠금이 없었다는 설계의 검증 근거이기 때문이다.
-   BATON GO의 `같은 요청 8건` 동시 처리 검증(상세와 공개 요약 문서). 테스트 조건이라 상세에서는 뜻이 분명하다.
-   경력과 개인 프로젝트 카드의 `확인한 범위`와 `아직 확인하지 않았습니다`. 구현, 로컬 검증, 실제 운영을 구분하는 원칙(AGENTS.md)이다.
-   청년정책메이트 카드의 `정책 40건`, `그중 12건은 신청 조건 일부`. 숫자가 작게 보일 수 있지만 조건 판정이 모든 정책과 모든 조건에 적용된다고 읽히지 않게 하는 범위 표시다. 지우면 사실보다 넓게 읽힌다.
-   Hope Commit 상세의 CI 링크 설명(`공개 v5.0.2에서 자동화 테스트 343개가 통과한 GitHub Actions 결과`). 성과 문장이 아니라 링크로 볼 수 있는 증거를 설명한다.
-   happyGallery 상세의 `회귀 테스트 16건`, CAL의 `Core 교차 테스트 5개`. 무엇을 확인하는 테스트인지 같은 문장에 있다.
-   군사법 도식의 `중단 단계 확인 후 재실행` 경로와 대표 사례 단계 `중단 시 재처리`. 처리 흐름을 설명하는 도식이다.
-   BATON 카드의 `운영자가 수신 측 기록을 확인해 결과를 확정합니다`. 결과를 모를 때 중복 전송을 피하려고 자동으로 다시 보내지 않는 설계 판단이다.
-   학습과 기술의 스터디 설명과 GitHub 기여 기록. 성과 문장이 아니라 활동 기록이다.

## 반영 및 검증 결과

사용자 요청대로 1~16번을 바로 반영했다. 새 성과나 수치는 더하지 않았다.

-   반영한 위치: 데이터 5개 파일(`timeline`, `projectSummaries`, `caseHighlights`, `projects`, `routeMeta`), `CareerSummary.jsx` 주석, README. 테스트 기대값 3곳(`App.test.jsx` 2곳, `Projects.test.jsx` 1곳)을 같은 의미의 새 문구로 고쳤고, 연표에 `RPS`, `자동화 테스트 N개`, `재실행`이 다시 들어오지 않게 기존 연표 검사에 한 줄을 더했다.
-   문구 스킬에 원칙 14와 `references/rules.md` 7절을 추가해 이번 판단을 남겼다. 전자영장 성능 조건은 고쳐 쓰지 않는 값으로 그대로 두고, 둘 위치만 상세로 정했다.
-   `check:file`(변경 파일 8개, 후속 2개, 문서 3개)과 대응 테스트, `font:check`(새 글자 없음) 통과.
