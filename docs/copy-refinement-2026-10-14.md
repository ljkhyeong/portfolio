# 포트폴리오 문구 검토 — 2026-10-14

## 요청과 범위

사용자가 포트폴리오 전체에서 추상적이고 이해하기 어려운 문구를 찾아 실무 용어로, 짧고 명확하게 고쳐 달라고 요청했다("확인해서 진행해줘"). 그래서 수정안을 정리한 뒤 바로 반영했다.

-   범위: `capture.mjs --all --expand --text --no-shot`로 모은 전 화면 문구 1,985줄(메인, 프로젝트 8개, BATON 서비스 6개, 문서 검색, 인쇄), 경로 메타, 공유 이미지 문구
-   10월 7일, 9일, 11일 검토에서 승인한 문구는 되돌리지 않았다. 메인 제목(`풀스택을 지향하는 주니어 개발자입니다.`, 2026-10-11 사용자 결정)과 메인 소개, 카드 문구는 이번 기준에 맞아 그대로 두었다.
-   새 성과나 수치는 더하지 않았다. 의미가 걸린 문장은 원본 코드로 확인했다(GO `LinkCreationFingerprint`의 비교 값, 검색 API `KnowledgeAnswerService`의 BM25 근거 조건).

## 판단 기준

이번에 남아 있던 문구는 크게 네 가지였다.

1. **결과를 흐리게 쓴 말**: `역할 정보가 어긋납니다`, `신뢰하기 어렵습니다`, `사용성이 떨어졌습니다`, `연결 상태를 점검합니다`. 무엇이 어떻게 되는지로 바꿨다.
2. **칸의 역할과 다른 내용**: `한계` 칸에 설계 설명, `확인` 칸에 구현 설명, `방법` 칸에 제목만 반복한 문장. 각 칸에 맞는 내용으로 옮기거나 바꿨다.
3. **같은 대상을 다르게 부른 말**: GO의 `조건`과 `요청 본문`, `재시도 화면`과 `다시 열기`, Hope Commit의 `설명`과 메인의 `리뷰 항목`, BATON의 `공개 환경`과 `배포 환경`, CAL의 `재전송`과 `재동기화`.
4. **뜻이 바로 안 읽히는 압축 표현**: `게시 요청 직렬화`, `웹 저장은 REST와 같은 Markdown 생성기`, `PostgreSQL API`, `키워드 근거 없으면 중단`.
