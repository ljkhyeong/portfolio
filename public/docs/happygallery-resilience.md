# happyGallery 외부 연동 복구 정책과 목록 조회 개선

2026년 11월 21일 로컬 작업 브랜치 `ae438032` 기준입니다. 사용자 제공 변경 기록을 요약했습니다. main 병합과 운영 배포는 수행하지 않은 상태이며, 이전 배포의 검증 결과와 구분합니다.

## 환불 자동 복구와 관리자 확인

환불 실행권 선점이 최초 실행을 포함해 10회에 도달하거나 생성 후 24시간이 지나면 자동 복구를 중단합니다. 횟수에는 결과 조회와 관리자 조회도 포함됩니다. PG 취소 금액이 없는 로컬 환불에는 적용하지 않습니다.

한도에 도달한 환불은 관리자 조회 결과가 미완료여도 확인 필요 상태를 유지하고 다음 실행을 예약하지 않습니다. 완료 응답은 결제키, 금액과 환불 거래키를 검증한 뒤 성공으로 기록합니다.

관리자 요청 상태 변경과 실행권 선점을 하나의 트랜잭션으로 묶었습니다. 외부 호출은 트랜잭션 밖에서 실행하고, 결과 저장 시 실행 토큰을 검사해 늦은 실패 응답이 성공 상태를 덮어쓰지 않게 했습니다.

## 결과 불명 알림의 중복 발송 차단

생성 후 24시간이 지나도 최종 결과를 확인할 수 없으면 자동 조회를 중단하고 직접 확인할 대상으로 남깁니다. 이는 수신 실패 확정이 아닙니다.

관리자 재처리는 기존 제공자 식별자를 보존해 결과만 재조회합니다. 식별자가 없거나 SMS 대체 발송의 결과가 불명확한 경우에는 재발송을 차단하고 제공자 이력 확인을 안내합니다.

## 서버와 브라우저 재시도

환불, 알림 전송과 결과 조회, 배송조회 등록에 지수 백오프와 지터를 적용했습니다. 실제 대기 시간은 계산한 상한의 50~100%입니다. DB에 저장한 작업 상태, 멱등 키와 다음 실행 시각을 사용하는 기존 구조를 유지했습니다.

브라우저는 네트워크 오류, 시간 초과, HTTP 408과 일부 5xx 조회 오류를 한 번만 재시도합니다. 429는 유효한 Retry-After가 3초 이내일 때만 재시도합니다. 인증 오류, 요청 취소와 상태 변경 요청은 자동 재시도하지 않습니다.

## 상품 목록과 후기 페이지

상품 목록은 전체 조회에서 서버 페이지 조회로 변경했습니다. 기본 24개이며 현재 페이지의 재고와 옵션만 조회합니다. SSR과 브라우저는 같은 검색 조건을 사용하고 페이지별 캐시를 분리합니다. 홈, 주문서와 sitemap에 쓰는 기존 전체 조회 API는 유지했습니다.

공개 후기는 누적 표시에서 10개씩 이전·다음 페이지로 교체하는 방식으로 변경했습니다. 회원 반응도 현재 페이지의 후기 ID만 조회합니다. 이전 데이터는 캐시에 남을 수 있으며 DB에서 삭제하지 않습니다. 가상화는 도입하지 않았습니다.

## 관측 데이터와 테스트 환경

-   Sentry Browser Tracing을 추가하고 동일 출처 API에만 추적 헤더를 전파합니다. 오류 이벤트뿐 아니라 transaction과 span에서도 URL 쿼리, 인증 헤더와 요청 본문 등 지정한 민감정보를 제거합니다. 모든 임의 필드의 개인정보 제거를 보장하지는 않습니다.
-   Prometheus의 기존 7일 보존에 4GB 용량 제한을 추가했습니다. manifest 수정 단계이며 운영 배포 전입니다.
-   컨테이너 로그는 파일당 20Mi, 최대 3개 회전 설정 예시와 운영 절차를 작성했습니다. 호스트 설치는 하지 않았습니다.
-   통합 테스트와 CI E2E의 MySQL 8.4.10, Redis 7.4.9-alpine 태그를 운영 manifest와 맞췄습니다. 운영 DB 업그레이드나 이미지 digest 고정은 아닙니다.

## 확인한 범위와 남은 검증

제공 기록에서 관련 JUnit, 프론트 단위 테스트와 빌드 통과를 확인했습니다. SSR 빌드와 fixture로 상품 첫 페이지 24개, 둘째 페이지 1개 및 기존 전체 API 미호출을 확인했습니다. 이 포트폴리오 작업에서 원본 프로젝트 테스트를 재실행하지 않았습니다.

표준 Gradle 전체 검사, 실제 MySQL 통합 테스트, 브라우저 E2E, 모바일 렌더링과 LCP 실측, 운영 Sentry 추적 연결은 남아 있습니다. Java 직접 컴파일과 JUnit 대체 실행을 표준 전체 검사 통과로 표현하지 않습니다. 응답 시간 감소나 운영 장애 감소는 측정하지 않았습니다.
