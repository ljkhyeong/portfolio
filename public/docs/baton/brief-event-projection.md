# BATON BRIEF 이벤트 중복 처리와 주간 보고서 생성

## 책임

BRIEF는 Core 개발 브랜치가 생성한 BATON 이벤트를 받아 현재 운영자가 확인해야 할 항목을 찾습니다. 두 번째 이벤트 형식(v2)에는 다음 운영 위험이 담깁니다.

-   담당자가 없는 역할
-   담당 종료가 임박했지만 후임자가 없는 역할
-   위험 요소가 기록됐고 책임 목록이 없거나, 인수인계에 포함할 업무 항목이 없거나 끝나지 않은 항목이 있거나, 역할 수행 자료가 없는 역할
-   서로 다른 2개 이상 회차에서 마감 뒤에도 끝나지 않은 반복 업무
-   담당 교대 시점이 가까운데 인수인계를 시작하지 않았거나 전달 및 수락 조건이 남은 인수인계

이 항목으로 운영 점검 목록을 만듭니다. 보고서 생성 요청을 받으면 해당 주간, BRIEF가 마지막으로 받은 이벤트 순번과 포함 항목을 함께 저장하며, 이후 이벤트가 바뀌어도 이미 만든 보고서는 수정하지 않습니다.

## 중복 및 이전 버전 처리

-   이벤트 ID, 본문 해시와 개정 번호를 비교해 같은 이벤트 재전달, 같은 ID의 다른 내용과 과거 개정 번호를 구분합니다. 개정 번호가 건너뛴 최신 이벤트는 적용하되 누락된 개정 구간을 함께 기록합니다.
-   수락한 이벤트 기록과 운영 점검 목록을 같은 PostgreSQL 트랜잭션에서 저장합니다.
-   저장한 이벤트 전체를 다시 읽어 기존 운영 점검 목록을 한 트랜잭션에서 교체할 수 있습니다.
-   같은 주간, 같은 마지막 수신 순번과 같은 항목으로 생성하면 기존 보고서를 반환합니다. 이후 상태가 바뀌었다가 같아진 경우에는 새 생성 번호로 별도 보고서를 저장합니다.
-   서비스 간 요청 인증 토큰(Bearer)은 현재 값과 직전 값을 잠시 함께 허용해 중단 없이 교체합니다.

## 테스트 기준

PostgreSQL 통합 테스트로 이벤트 중복, ID 충돌, 지원하지 않는 버전, 과거 개정 번호 차단, 건너뛴 최신 개정 적용 및 누락 구간 기록, 운영 점검 목록 전체 다시 생성과 동일 보고서 중복 생성을 확인했습니다. JSON 계약 패키지 `2.0.0-rc.1` 기준으로 실제 Core와 BRIEF 실행 JAR를 로컬 HTTP에서 연결해 Core의 역할 및 인수인계 정보 변경이 BRIEF 운영 점검 목록에 반영되는지, 장애 재시도, 동일 이벤트 재전달과 현재 및 직전 Bearer 토큰을 함께 허용하는 교체 구간을 확인했습니다. 별도로 BRIEF의 Caddy 내부 인증서 HTTPS 앞단에는 계약 예시 JSON을 전송해 인증과 수신을 확인했습니다.

## 현재 범위

최신 구현은 원격 개발 브랜치에 있으며 공개 저장소의 `main`에는 아직 반영하지 않았습니다. Core 개발 브랜치와 BRIEF의 로컬 연동은 JSON 계약 패키지 `2.0.0-rc.1` 및 로컬 HTTP 기준으로 확인했습니다. 입력 규칙을 강화한 현재 `2.0.0-rc.2`는 Core의 실제 JSON 생성 코드와 다시 검증해야 합니다. v2는 Core가 판정한 다섯 가지 조직 연속성 신호를 담으며, 이전의 인수인계 진행 중단, 미완료 반복 업무와 결정 후속 조치 지연을 받는 첫 번째 이벤트 형식(v1)도 계속 처리합니다. 실제 Core에서 Caddy로 보내는 HTTPS 전달, 공인 DNS 및 자동 발급 TLS 인증서와 두 스테이징 호스트 사이의 원격 전달 및 장기 운영 배포도 아직 검증하지 않았습니다.
