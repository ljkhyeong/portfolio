# BATON BRIEF 점검 상태 반영과 발행 보고서 수정 방지

## 책임

Core는 조직 데이터를 기준으로 다음 5개 운영 상태를 점검합니다. BRIEF는 이 점검 결과를 다시 판정하지 않고 현재 점검 항목과 주간 보고서에 반영합니다.

-   담당자가 없는 역할
-   담당 종료가 임박했지만 후임자가 없는 역할
-   위험 요소가 있는 역할 중 책임 목록·완료된 인수인계 업무·역할 수행 자료가 부족한 역할
-   서로 다른 2개 이상 회차에서 마감 뒤에도 끝나지 않은 반복 업무
-   담당 교대가 가까운데 인수인계를 시작하지 않았거나 전달 및 수락이 끝나지 않은 인수인계

Core 이벤트의 활성 상태는 `ACTIVE`, 해소 상태는 `RESOLVED` 점검 항목으로 그대로 저장합니다. 원본 심각도도 다시 계산하지 않고 `CRITICAL`과 `WARNING`을 각각 `HIGH`와 `MEDIUM`으로 표시합니다. 주간 보고서에는 해당 주간, 마지막 이벤트 순번과 포함 항목을 저장하며 한 번 발행한 주간 보고서는 수정하지 않습니다.

## 중복 및 이전 버전 처리

-   이벤트 ID, 본문 해시와 점검 상태의 버전 번호(`revision`)를 비교해 같은 이벤트 재전달, 같은 ID의 다른 내용과 과거 버전 번호를 구분합니다. 버전 번호가 건너뛴 최신 이벤트는 적용하되 누락된 버전 구간을 함께 기록합니다.
-   수락한 이벤트 기록과 운영 점검 목록을 같은 PostgreSQL 트랜잭션에서 저장합니다.
-   저장한 이벤트 전체를 다시 읽어 기존 운영 점검 목록을 한 트랜잭션에서 교체할 수 있습니다.
-   같은 주간, 같은 마지막 수신 순번과 같은 항목으로 생성하면 기존 주간 보고서를 반환합니다. 이후 상태가 바뀌었다가 같은 항목으로 돌아와도 새 생성 번호의 주간 보고서를 저장하고 이전 주간 보고서는 그대로 둡니다.
-   서비스 간 요청 인증 토큰(Bearer)은 현재 값과 직전 값을 잠시 함께 허용해 중단 없이 교체합니다.

## 테스트 기준

PostgreSQL 통합 테스트로 5개 점검 결과의 `ACTIVE` 및 `RESOLVED` 반영, 이벤트 중복, ID 충돌, 과거 버전 차단, 저장 이벤트 기반 점검 목록 재생성과 같은 주간 보고서의 중복 생성을 확인했습니다.

실제 서비스 연동과 HTTPS 앞단 검증은 다음과 같이 나눠 확인했습니다.

-   JSON 계약 패키지 `2.0.0-rc.1` 기준으로 실제 Core 실행 JAR에서 BRIEF 실행 JAR로 로컬 HTTP 이벤트를 보냈습니다.
-   내부 서비스용 Caddy에서는 실제 Core와 BRIEF JAR, MySQL과 PostgreSQL을 실행해 로그인, 멤버십 및 접근 키 확인, HTTPS 보고서 생성과 조회, ETag, 재시도와 토큰 교체를 확인했습니다.
-   이 기록은 확인 당시의 계약과 로컬 환경에 대한 결과입니다. 최신 기능 전체의 공개 배포를 뜻하지 않습니다.

## 현재 범위 — 2026-09-12

[공개 main 2a96b04](https://github.com/ljkhyeong/baton-brief/tree/2a96b04)에서 업무 종류·심각도별 점검 목록과 주간·시간대별 보고서 이력을 조회합니다. 보고서 비교에도 ETag를 적용해 변경이 없으면 304를 반환합니다. Core 화면에서는 조회 조건을 유지한 채 보고서 링크 복사·인쇄·PDF 저장을 제공합니다.

Core가 보낸 판정과 심각도, 생성 당시 보고서 본문은 유지합니다. 현재 업무명과 생성 이후의 변경 안내는 별도로 조회해 과거 보고서를 덮어쓰지 않습니다. 로컬 HTTP·내부 Caddy HTTPS 연동 기록을 확인했으며 실제 원격 배포와 외부 경보 수신은 미검증입니다.
