# BATON GO 같은 요청에서 링크 1건만 생성

## 문제 상황

링크를 저장한 뒤 응답이 유실되거나 여러 서버가 같은 요청을 동시에 받으면 링크가 중복 생성될 수 있습니다.

## 결정

-   클라이언트가 보낸 UUID를 멱등 키로 사용합니다.
-   표준화한 요청 해시를 함께 저장해 같은 키의 다른 요청을 거절합니다.
-   HMAC-SHA256으로 같은 입력에서 같은 링크 코드를 만듭니다.
-   DB `UNIQUE` 제약으로 동시 요청의 중복 저장을 차단합니다.

## 적용 시 제약

멱등 기록의 보관 기간과 정리 정책이 필요합니다. HMAC 키를 교체하거나 DB를 복구할 때 기존 링크가 유지되도록 별도 운영 절차도 필요합니다.

## 확인

같은 요청 8건을 동시에 보내 링크와 생성 예약이 각각 1건만 생성되는지 통합 테스트로 확인했습니다.
