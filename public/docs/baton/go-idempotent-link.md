# BATON GO 같은 요청에서 링크 1건만 생성

## 문제 상황

링크를 저장한 뒤 응답이 유실되거나 여러 서버가 같은 요청을 동시에 받으면 링크가 중복 생성될 수 있습니다.

## 결정

-   클라이언트가 링크 생성 요청마다 보내는 고유 ID(UUID)의 SHA-256 해시를 저장해 기존 링크 생성 처리 기록을 찾습니다.
-   재요청이면 저장된 대상 시스템, 경로, 사용 목적, 활성 시각과 만료 시각을 직접 비교하고 하나라도 다르면 충돌로 거절합니다.
-   같은 UUID와 서버 비밀 키로 HMAC-SHA256을 계산해 같은 링크 코드를 만듭니다.
-   DB `UNIQUE` 제약으로 동시 요청의 중복 저장을 차단합니다.

## 적용 시 제약

UUID 처리 기록의 보관 기간과 정리 정책이 필요합니다. HMAC 키를 교체하거나 장애를 복구할 때 기존 링크가 바뀌지 않도록 DB 백업과 HMAC 키를 같은 시점 기준으로 보관하고 복원해야 합니다.

## 확인

같은 요청 8건을 동시에 보내 링크와 링크 생성 처리 기록이 각각 1건만 생성되는지 통합 테스트로 확인했습니다.
