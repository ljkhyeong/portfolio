# BATON Core 헥사고날 아키텍처

## 문제 상황

조직, 시즌, 권한, 루틴처럼 서로 연결된 업무 규칙이 HTTP와 DB 구현에 직접 묶이면 기능을 바꿀 때 영향 범위를 확인하기 어려웠습니다.

## 결정

-   도메인과 애플리케이션 규칙을 중심에 둡니다.
-   HTTP 입력과 DB 저장은 어댑터로 분리합니다.
-   모듈 의존 방향을 정책 테스트로 확인합니다.
-   모든 클래스에 인터페이스를 만들지 않고 실제 교체 지점에만 포트를 둡니다.

## 적용 시 제약

HTTP 컨트롤러와 DB 저장 코드가 업무 규칙에 직접 의존하지 않게 했지만 포트와 어댑터 타입은 늘어났습니다. 추가 매핑 코드가 과도하게 늘지 않도록 도메인 모델에는 현재 필요한 JPA 매핑 어노테이션을 유지했습니다.

## 확인

Gradle 빌드에서 모듈별 컴파일과 의존성 정책 테스트를 실행해 금지한 모듈 참조가 있으면 빌드를 실패하도록 했습니다.
