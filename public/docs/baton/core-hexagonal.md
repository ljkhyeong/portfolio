# BATON Core 업무 규칙을 HTTP와 DB 코드에서 분리한 구조

## 문제 상황

조직, 시즌, 작업 공간 공유 키와 반복 업무처럼 서로 연결된 규칙이 HTTP 요청 처리와 DB 저장 코드에 직접 묶이면 기능을 바꿀 때 영향 범위를 확인하기 어려웠습니다.

## 결정

-   인수인계 상태 변경과 반복 업무 규칙은 애플리케이션 및 도메인 모듈에 둡니다.
-   컨트롤러는 HTTP 요청을 변환한 뒤 해당 업무 기능만 호출하도록 분리합니다.
-   DB 저장과 외부 연동처럼 교체할 필요가 있는 지점에만 인터페이스를 둡니다.
-   업무 규칙 모듈이 웹 및 DB 구현 모듈을 참조하지 않도록 의존성 테스트로 검사합니다.

## 적용 시 제약

HTTP 컨트롤러와 DB 저장 코드를 업무 규칙에서 분리하면서 인터페이스와 변환 타입은 늘어났습니다. 추가 변환 코드가 과도하게 늘지 않도록 현재 필요한 JPA 매핑은 도메인 모델에 유지했습니다. 이 구조는 교체 지점에만 인터페이스를 두는 헥사고날 아키텍처 방식으로 구현했습니다.

## 확인

Gradle 빌드에서 모듈별 컴파일과 의존성 테스트를 실행해 업무 규칙 모듈이 웹 및 DB 구현 모듈을 참조하면 빌드가 실패하도록 했습니다.

현재 공개용 설계 기준은 PRD 8건과 ADR 20건입니다. Google, Naver 및 이메일 계정 세션과 기존 구성원 연결을 구현했습니다. Core와 CAL의 1.0.0 계약, Core와 ROUND의 로컬 연동, Core와 BRIEF의 2.0.0-rc.1 로컬 HTTP 및 내부 서비스용 Caddy HTTPS를 확인했습니다. GO와 RELAY의 실제 런타임 연결, WATCH 공개 콜백, BRIEF 공개 2.0.0-rc.2 이벤트 경로용 Caddy와 공인 DNS 및 TLS는 확인하지 않았습니다.
