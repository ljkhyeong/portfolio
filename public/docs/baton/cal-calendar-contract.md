# BATON CAL 일정 JSON 수신과 캘린더 구독

## 책임

CAL은 Core가 확정한 시즌 일정과 마감을 읽기 전용 iCalendar(`.ics`) 피드로 제공합니다. Core는 공개한 일정 JSON 형식 1.0.0에 맞춰 일정 한 건의 최신 전체 데이터과 개정 번호를 보내고, CAL은 같은 일정과 이전 번호가 다시 들어오는지 확인한 뒤 캘린더 형식으로 변환합니다. 어떤 일정을 포함하고 누가 구독할 수 있는지는 Core가 결정합니다.

## 일정 및 구독 처리

-   이벤트 ID, 일정 ID, 개정 번호와 내용 해시를 비교해 적용, 중복, 이전 버전과 충돌을 구분합니다.
-   일정 식별값(`UID`)은 고정하고 원본 개정 번호를 캘린더 변경 순번(`SEQUENCE`)으로 사용해 변경 및 취소를 구분합니다.
-   같은 일정에서는 같은 `.ics`, 캐시 확인값(`ETag`)과 최종 변경 시각(`Last-Modified`)을 생성합니다. 캘린더 앱이 이전 ETag를 보내고 일정이 바뀌지 않았으면 본문 대신 `304 Not Modified`를 반환합니다.
-   구독 토큰은 한 번만 반환하고 DB에는 SHA-256 해시만 저장합니다.
-   토큰을 교체하거나 폐기하면 이전 구독 URL은 더 이상 피드를 반환하지 않습니다.

## 검증 기준

PostgreSQL Testcontainers, iCal4j 4.3.0과 `.ics` 기대값 파일로 같은 일정 재전송, 과거 및 충돌 개정 번호, 저장 데이터 기반 재생성, 서머타임 전환(DST)과 자정 경계, 취소 일정, UTF-8 줄 접기, 변경 없음 응답(`304 Not Modified`)과 구독 토큰 동시 교체를 확인했습니다. 1.1.0-rc.1에서는 대표 OCI 백업 및 복구, 복구 세대 번호를 이용한 이전 작업의 늦은 결과 차단도 로컬에서 검증했습니다.

일정 JSON 형식 1.0.0 기준으로 Core의 실제 일정 JSON 생성 코드로 만든 데이터를 CAL 컨테이너에 보내 생성, 변경, 취소와 순서가 바뀐 전달이 올바르게 처리되는지도 별도로 확인했습니다.

## 현재 범위

-   정식 JSON 규격 `1.0.0`: Core 일정 JSON 생성 코드로 만든 데이터와 CAL 컨테이너의 호환성 검증 완료
-   공개 `main`의 미게시 후보 `1.1.0-rc.1`: 입력 제한, HTTP 캐시, DB timeout, 구독 및 시즌 동시성, iCal4j 4.3.0과 대표 OCI 복구 검증 완료, 공개 릴리스와 Core 적용 전
-   운영 미검증: 운영 자격 증명, 공개 캘린더 구독과 DB 복구 후 전체 일정 재전송

`1.1.0-rc.1`은 JSON 전체 128 KiB, 필드명 64자, 중첩 16단계, 숫자 10자리와 토큰 256개로 입력을 제한합니다.
