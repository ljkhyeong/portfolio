# BATON RELAY 응답을 잃은 이벤트의 중복 전달 차단

## 문제 상황

등록된 HTTP Webhook이나 SQS FIFO 큐가 BATON 이벤트를 받았지만 RELAY가 응답을 받기 전에 종료되면 성공 여부를 모른 채 같은 이벤트를 다시 전달할 수 있습니다.

## 결정

-   대상 호출 전에 전송 시도 이력과 대상용 중복 방지 키를 저장합니다.
-   DB에서 다른 서버가 처리 중이지 않은 작업만 선택하고, 외부 요청 중에는 DB 연결을 반환합니다.
-   처리 권한에 만료 시간을 두고, 다른 서버가 이어받아도 같은 전송 식별자를 유지하며 이전 서버의 늦은 결과는 저장하지 않습니다.
-   대상이 처리했는지 확인할 수 없으면 결과 미확인 상태(`OUTCOME_UNKNOWN`)로 멈춥니다.

## 적용 시 제약

중복 전달 방지를 우선하므로 결과를 모르는 작업은 자동 재전송하지 않습니다. 대상 시스템의 결과 조회나 운영자가 실제 처리 결과를 확인하고 상태를 확정하는 절차가 필요합니다.

## 확인

같은 이벤트 재전달, 처리 서버 중단, 다른 서버가 가져간 작업의 처리 기한 만료, 늦은 응답과 처리 결과 미확인 상태를 통합 테스트로 확인했습니다.
