# BATON RELAY 응답 유실 시 중복 발송 방지

## 문제 상황

외부 공급자가 메시지를 받았지만 애플리케이션이 응답을 받기 전에 종료되면 성공 여부를 모른 채 다시 전송할 수 있습니다.

## 결정

-   외부 호출 전에 전송 시도 이력과 전송업체용 멱등 키를 저장합니다.
-   `SKIP LOCKED`로 다른 작업자가 처리 중이지 않은 작업만 선점합니다.
-   작업 선점 만료 시간을 두고, 시간이 지나 다른 작업자가 이어받아도 같은 전송 식별자를 유지합니다.
-   성공 여부를 확인할 수 없으면 결과 미확인 상태(`OUTCOME_UNKNOWN`)로 멈춥니다.

## 트레이드오프

중복 발송 방지를 우선하므로 결과를 모르는 작업은 자동 재전송하지 않습니다. 전송업체 결과 조회나 운영자가 실제 전송 결과를 확인하고 상태를 확정하는 절차가 필요합니다.

## 확인

같은 이벤트 재전달, 작업자 중단, 작업 선점 시간 만료, 늦은 응답과 처리 결과 미확인 상태를 통합 테스트로 확인했습니다.
