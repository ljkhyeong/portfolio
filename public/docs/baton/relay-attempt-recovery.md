# BATON RELAY 전송 시도 복구

## 문제 상황

외부 공급자가 메시지를 받았지만 애플리케이션이 응답을 받기 전에 종료되면 성공 여부를 모른 채 다시 전송할 수 있습니다.

## 결정

-   외부 호출 전에 전송 시도와 provider 멱등 키를 저장합니다.
-   SKIP LOCKED와 lease token으로 여러 작업자가 같은 작업을 처리하지 않게 합니다.
-   lease가 만료되어도 같은 전송 식별자를 유지합니다.
-   성공 근거가 없으면 `OUTCOME_UNKNOWN`으로 멈춥니다.

## 트레이드오프

중복 발송 방지를 우선하므로 결과를 모르는 작업은 자동 재전송하지 않습니다. 공급자 결과 조회나 운영자 조정 절차가 필요합니다.

## 확인

중복 수신, 작업자 중단, lease 만료, 늦은 응답과 결과 불명 상태를 통합 테스트로 확인했습니다.
