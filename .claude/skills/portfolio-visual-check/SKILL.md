# 포트폴리오 화면 확인

자동 검사는 기계적인 결함을 빠르게 찾는다. 줄바꿈 품질, 정렬, 시각적 위계는 캡처 이미지를 직접 보고 판단한다. 이전 검토에서 페이지는 모두 확인했지만 도식의 글자 대비 문제를 놓친 적이 있다. 그래서 방문한 페이지 수보다 **변경한 요소**를 확인했는지가 중요하다.

## 1. 개발 서버 준비

`http://127.0.0.1:5173`이 응답하는지 먼저 확인한다. 응답이 없으면 내장 브라우저의 `preview_start`에 `.claude/launch.json`의 `portfolio-dev`를 지정해 실행하거나, `npm run dev`를 백그라운드로 실행한다. 이미 떠 있는 서버를 재사용하고, 직접 시작한 서버만 작업이 끝난 뒤 종료한다.

## 2. 캡처와 자동 검사

```bash
node .claude/skills/portfolio-visual-check/scripts/capture.mjs --routes /,/projects/happygallery --label happygallery-status
```

| 상황                    | 옵션                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------- |
| 변경한 화면 확인        | `--routes <경로,...>` (기본 너비 1440, 390)                                         |
| 상세 페이지 레이아웃    | `--widths 1920,1440,390` (README의 상세 기준은 1440·1920px)                         |
| 공통 스타일·반응형 변경 | `--widths 1440,1024,768,390,320`                                                    |
| 프로젝트 상세 도식      | `--selector .editorial-diagram__viewport --contrast .editorial-diagram --scale 2`   |
| BATON 서비스 도식       | `--selector .baton-service-flow__viewport --contrast .baton-service-flow --scale 2` |
| 접힌 설명 포함 확인     | `--expand --full`                                                                   |
| 문구 전수 수집          | `--all --expand --text --no-shot` → `text/unique-lines.tsv`                         |
| 404 화면                | `--routes /없는-경로` (routeMeta에 없는 경로는 404여도 실패로 보지 않음)            |

출력은 `output/playwright/<label>-<날짜>/`에 저장되며 Git에서 제외된다. 새 최상위 산출물 폴더를 만들지 않는다.

종료 코드는 0이면 모두 통과, 1이면 실패한 검사가 있음, 2이면 스크립트 실행 오류다. 실패 항목은 `report.json`의 `results[]`에서 확인한다.

| 검사          | 판정                                                                                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 가로 넘침     | 문서 전체가 화면보다 넓을 때만 실패. 도식, 탭처럼 의도한 가로 스크롤 영역 안의 요소는 원인 목록에서 제외한다.                                                                      |
| 깨진 이미지   | 끝까지 스크롤해 지연 로딩을 실행한 뒤 불러오지 못한 `img`                                                                                                                          |
| 브라우저 오류 | `pageerror`, `console.error`, 요청 실패, 같은 출처의 4xx·5xx 응답. 원인이 확인된 외부 요인만 `--ignore-console`로 제외한다.                                                        |
| 도식 글자     | 글자와 겹치는 사각형 중 어느 것도 글자를 모두 감싸지 못하면 넘침이다. 테두리 있는 노드 상자면 실패, 테두리 없는 라벨 마스크면 경고(`svgLabelWarnings`)로 기록하고 캡처로 판단한다. |
| 글자 대비     | WCAG AA 기준. 일반 글자는 4.5, 24px 이상이거나 18.66px 이상 굵은 글자는 3.0. `uncertain`은 배경 이미지나 그라디언트가 있다는 뜻이므로 캡처로 판단한다.                             |

## 3. 캡처 확인

변경한 요소가 보이는 캡처는 Read 도구로 직접 확인한다. 다음 항목은 자동 검사가 잡지 못한다.

-   제목과 강조 구간의 줄바꿈, 한 글자만 다음 줄로 넘어간 줄
-   HTML 글자와 이미지의 겹침, 카드와 열의 정렬
-   모바일에서 숨기거나 다시 배치한 요소가 의도대로 보이는지
-   인쇄 화면(`/portfolio/print`)의 밝은 배경과 A4 배치. PDF 자체는 `portfolio-artifacts` 스킬로 확인한다.

## 4. 상호작용 확인

갤러리 확대 창, 메뉴, 접기와 펼치기, 키보드 초점, 섹션 이동은 내장 브라우저(`mcp__Claude_Browser__*`)로 확인한다. `resize_window`의 `mobile` 프리셋으로 390px 동작도 확인하고, 끝나면 `desktop`으로 되돌린다. 같은 동작을 여러 경로에서 반복해야 하면 `output/playwright/` 아래에 짧은 스크립트를 따로 둔다.

검색 화면(`/search`)의 결과와 답변 상태는 검색 API가 있어야 확인할 수 있다. API 없이 확인한 경우에는 결과에 그 사실을 적는다.

## 5. 결과 기록

`output/validation/last-run.md`에 다음 내용을 남긴다. 실행하지 않은 검사를 통과로 쓰지 않는다.

-   확인한 경로, 화면 너비와 옵션
-   실패 항목, 원인과 조치. 이번 변경과 무관한 기존 결함은 수정하지 않고 보고한다.
-   직접 확인한 캡처와 확인하지 못한 상호작용

## Playwright 위치

프로젝트 의존성에는 Playwright가 없다. 스크립트는 `PLAYWRIGHT_MODULE`, 프로젝트 `node_modules`, Codex 런타임과 npx 캐시 순서로 찾는다. 브라우저는 `CHROME_PATH`, 설치된 Chrome, Playwright 내장 Chromium 순서로 실행한다. 모두 없으면 사용자에게 알린다. `package.json`에 Playwright를 추가하는 것은 의존성 변경이므로 사용자 승인 없이 하지 않는다.
